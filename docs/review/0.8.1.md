# PR #31 / 0.8.1 レビュー・検証

対象: Minecraft 1.21.1のNeoForge / Forge。シエルの非公開扱いは意図した仕様であり、公開内容へ追加しない。1.20.1への移植・公開は今回の対象外。

## 指摘と修正

1. **P1 自動招集で作業可能な個体を除外する。** 候補全員で運搬容量を確認した後、近い個体へ絞るため、6スタック必要なケーキの工程で唯一バックパックを持つ個体が除外された。未修正コードで再現テストが失敗したことを確認。各工程の運搬容量・液体/化学タンク・採掘/伐採能力を同じ個体で満たす担当者を必ず残し、不要な追加人員は再び除く。明示選択と自動選択の両経路を維持。
2. **P1 Forgeで消えた機能の古いLazyOptionalが有効なままになる。** Providerがnullを返す場合にも前のハンドラーを無効化。除去と置換の回帰テストを追加。
3. **P2 Forgeの装置への静的参照が解放されない。** WeakHashMapの値のProviderがキーのBlockEntityを強参照し、弱いキーが回収されない。値もWeakReferenceで保持する。
4. **検証不足 Forgeの実ワールドGUI。** 共通のGUIハーネスをForge向けに変換する開発用オプションを追加。両ローダーで20画面・PNG在庫欄105点・検索/ソート/インベントリキーの操作を検証する。通常JARへのハーネス混入を検査。
5. **公開時の成果物の取り違え・再ビルド・重複送信の防止。** 両ローダーのCIと実Mekanism連携の成功、タグ・PR・実際のマージ用テストツリー、正しいN/F JAR、所定のテスト件数とGUI完了を照合してから成果物を昇格する。公開前にJARを添付しないdraftを予約し、失敗時の重複送信を防ぐ。タグ作成だけでは公開しない。
6. **Forgeテストの古いワールド・成功ログの混入。** 実行前にテストワールドと前のログを削除する。

## 検証記録

- 修正前: 自動招集の追加テストが `Automatic recruitment discarded the only capable worker` で失敗。
- 修正後ローカルNeoForge: 全359件のGameTest成功。
- 翻訳・モデル・実績73件・支援者名簿の静的検査が成功。
- 公開時のソース・ローダー・失敗したCI・実際のテストツリーを検証する回帰テスト5件が成功。
- 最終の両ローダーCI、Forge固有2件とGUI検査はPRの最新チェック結果を参照する。

## 公開手順

両ローダーの最終CI成功後にPRを1.21.1へマージし、検証済みツリーとの一致を確認。`v0.8.1`を作成し、Publish CurseForgeを`verified_run_id`と`release_tag`付きで実行する。0.8.1はBetaとして、1.21.1Nと1.21.1Fの両方を公開する。GitHub Releasesには配布JARを添付しない。
