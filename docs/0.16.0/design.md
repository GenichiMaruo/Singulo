# 0.16.0 宇宙現象を封じ込める設備

基点: `feature/0.16.0` / `f2fb5932`、Minecraft 1.21.1、NeoForge、Java 21。
以下は実装開始時の設計と仮バランス。実装・検証の実績とは区別する。

## 進行

1. 段階 2–3: 重力懸垂タンクで一般の FluidStack 液体・気体を保管し、既存パイプを接続する。
2. 段階 5: 既存 Jet Forge で核パスタを製造する。新しい蓄電装置を材料・起動条件にしない。
3. 核パスタで有限容量の積層蓄電設備を作り、潮汐紡糸設備で光る繊維を製造する。
4. 潮汐繊維と Collapsar Ingot を使い、既存の対になったワームホールへ通行用開口部を追加する。
5. Collapsar 製の加工カセットで既存 Jet Forge を最大 4 バッチへ拡張する。炉殻・点火処理は既存のものを使う。

装備・ツール本体は追加しない。既存 Survey Glasses を配管の監視に拡張する。

## 設備と見た目

- **重力懸垂タンク**: 上側の保持冠と細い脚、開いた縦長の 5×7×5 ケージ。液面は天井から下へ伸びる。流体の実テクスチャ・色、量、入口と出口を示す。仮容量 16,000,000 mB。既存 32,000 mB タンクの 500 倍、巨大設備として有限にする。FluidStack と別 API の Mekanism chemical は混同しない。
- **核パスタ積層蓄電庫**: 7×7×7 の重い上下ヨークと浮いた複数層。充電すると層が中央へ圧縮され、放電時は外側の導体へ流れが走る。仮容量 8 TFE、転送 2 GFE/t。既存 SMES Module は 2 GFE / 100 MFE/t、Jet Forge の標準需要は 250 MFE/t なので、後半の大規模設備として用途を分ける。入力された分だけを蓄え、発電や容量変更によるエネルギー生成は行わない。
- **潮汐紡糸機**: 細長い 5×7×13。封じ込め核から伸びる光る糸を反対側のスプールが巻く。圧縮する蓄電庫・照射する Jet Forge と動きを区別する。有限の素材・冷却材・電力から潮汐繊維を作り、停止・破損・アンロードで進行や予約物を消さない。
- **通行用縫合口**: 既存の物流用ワームホールを残し、アップグレード済みの両端に縦の四角い開口部を縫い開く。片端だけの導入、相手が閉鎖・未ロード、安全な出口なしでは転送しない。プレイヤーが歩いて入った時だけサーバーが処理し、再転送のクールダウンを設ける。
- **並列照射**: 1–4 個の素材を照射室で並べ、処理数を表示する。開始時に数量を確定して保存し、途中のアップグレード着脱で成果物・消費量を変えない。

## 保存・入出力・安全

- 整数型の容量上限、転送上限、残量を常に確認する。simulate は状態を変えない。
- 予約済み素材・冷却材・成果物・数量・進行・電力は保存する。出力満杯なら待ち、地面へ捨てない。
- 構造の未ロードを破損と区別し、検査目的でチャンクをロードしない。静的キャッシュは寿命と容量を制限する。
- 配管の方向表示は実転送に基づく。観測者がいる時だけ、範囲と頻度を制限して同期する。設定の複雑化は行わない。
- 別次元移動は相手の読み込み済み状態・ワールド境界・衝突・危険ブロック・足場を確認する。安全な出口を確認する前にプレイヤーを動かさない。
- 新設備の構造部品は既存の部材を活かし、装置本体のレシピは形と役割が分かる定形配置にする。
- 通常の描画パイプラインで動作させ、強制の画面フラッシュ・高速点滅・全画面後処理を追加しない。遠距離では線や粒子を間引く。

## 段階的な検証

配管表示、予約型バッチ、有限容量・保存、構造と入出力、通行と安全な出口、描画・翻訳の順に実装し、各段階で回帰を確認する。最後に全 GameTest、Python、GUI、製品 JAR の検査を行う。未実装・未検証は結果報告で具体的に記載する。
