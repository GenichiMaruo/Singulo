# 0.16.0 独立レビュー指摘への対応

対象は初期実装 `fe9d6c85`。以下の2件を修正前の実行テストで再現し、修正後に回帰テストを通した。

## 採掘・即時再設置による旧メニューからの複製

別プレイヤーが紡糸機を閲覧中にサバイバル採掘し、同じ座標へ採掘アイテムを置き直すと、旧メニューの `stillValid` が別個体を受理した。
旧メニューは元の在庫を参照したままなので、再設置先に7個、閲覧者にも7個の材料が残ることを実際に再現した。

Minecraft / NeoForge 1.21.1の処理順も確認した。

- サバイバル採掘の `ServerPlayerGameMode.destroyBlock` は、元のBlockEntityを確保し、ブロックを除去した後に `playerDestroy` からドロップを作る。
- `Level.destroyBlock` は、ドロップを作った後にブロックを除去する。
- クリックのサーバーパケット処理は、現在のメニューIDと `stillValid` を確認してから `clicked` を呼ぶ。

修正では、サーバーメニューを在庫を持つ元のBlockEntityへ直接結び付けた。同じ座標・同じ型だけでは再利用できない。
ブロック除去時にはメニューアクセスを先に退役させ、他プレイヤーの閲覧も即座に閉じる。
`stillValid` に加え、通常クリック・Shiftクリック・直接のquick-moveとスロットの挿入・取得可否の判定にも無効化を適用した。
退役状態は保存しないため、採掘アイテムから作られた新しい個体は通常どおり使える。

両方の破壊API経路で、次をテストした。

- 再設置後も材料の総数は7個。旧メニューからは取得できない。
- 旧メニューへの通常クリックとquick-moveも拒否する。
- 閲覧者の画面は直ちに閉じる。
- 再設置先で新しいメニューを開けば7個を正常に取得でき、その後も旧メニューから追加取得できない。

## 紡糸機の通常自動化に必要な接続面

初期構造では、制御卓の前・下以外の隣接位置がフレームまたは必須の空気だった。
電力ケーブル、流体パイプ、搬入出ホッパーを同時に置くと構造が成立しないことを再現した。

制御卓の左右の足元2か所をサービス開口にした。電力と冷却材を左右から接続し、前・下をアイテム搬入出に使える。
既に初期形状を組んでいる場合は、その2個のフレームを取り外して配線を通せる。内部の必須空間は維持している。
接続説明は日本語・英語・簡体字・繁体字・韓国語のハンドブックへ反映した。

実行テストでは、形成済みの核・初期電力ゼロから、通常のHorizon Bus、流体パイプ、搬入出ホッパーを使用した。
外部から材料と500 mBの液体ヘリウムを供給し、電力を受け取り、1回の加工を完了して4個の潮汐繊維をホッパーへ出力できた。
ワームホールや制御卓への直接の資源注入は使用していない。
