## 装置の様子の報告（machine/MachineReport）

- 1台の装置の様子を1つの報告にまとめる: 状態（画面の状態の記号 `Panel.Status` と同じ7つ）・短い言葉（画面のヘッダーと同じ翻訳キー）・理由の続き・進み具合・蓄電・使う/作る電力（FE/t）・装填中の触媒と残り・マルチブロックの足りない部品と、空けておく所をふさぐブロックの数。
- 報告を出す装置（`MachineReport.Source`）: 加工機とマルチブロックのコントローラー（`MachineBlockEntity`。待機中は `MachineDiagnosis` で理由を出す）・触媒装置（`CatalystDeviceBlockEntity`。発電機は作っている電力）・熱電発電機・専用の画面を持つ大型の装置（ペンローズ炉の炉心制御装置・降着ジェット鍛造炉・創世炉・ワームホール生成器・懸濁貯留槽などの宇宙の装置。画面のヘッダーと同じ分け方）。ほかの装置は電力の量だけ（Jade・WTHIT は自分で電力を出すので、行は出ない）。
- `MachineReport.of(level, pos)`: マルチブロックの部品ならコントローラーの報告。組み上がっていないマルチブロックのコントローラーには足りない部品を付け、状態を未形成にする（置いた直後の装置は、まだ状態を求めていないため）。大きさを選べる形は、足りない数がいちばん少ない大きさで数える。数え方はホロ投影機のチャットの報告と同じ（`HoloProjectorItem.shortfall` に分けた）。
- NBT で送る（理由の行は、文字だけの行と飾りのある行で NBT の型が違うので、1行ずつ包んで並べる）。
- GameTest `reportsExplainIdleMachinesAndMissingParts`（土を入れた焼成炉の理由、未形成の縮退圧縮炉の足りない部品の数、送っても変わらないこと）。

## Jade・WTHIT（compat/jade・compat/wthit）

- どちらも任意の連携。本体の jar の API でコンパイルし（`maven.modrinth:jade`・`maven.modrinth:wthit`、版は gradle.properties）、開発中の起動には `-PwithJade`・`-PwithWthit` を付けたときだけ入れる（WTHIT は Bad Packets も入れる）。
- Jade: `@WailaPlugin` の `SinguloJadePlugin`。サーバーのデータはすべてのブロックに登録し、`shouldRequestData` で報告を出す装置・マルチブロックの部品とコントローラーだけに絞る（見るたびにサーバーへ頼むため）。部品にはブロックエンティティがないが、ブロックのクラスで頼めるので、部品を見てもコントローラーの様子が出る。
- WTHIT: `waila_plugins.json` の `singulo:machine`（common と client）。WTHIT はブロックエンティティのあるブロックにだけデータを頼むので、部品を見ても出ない。設定の切り替え `singulo:machine`。
- 両方の連携が読み込まれることを `runGameTestServer -PwithJade`・`-PwithWthit` のログで確かめた。表示はクライアントで確認する。
- `-PwithJade` で GameTest を全部流すと、仮のプレイヤーがログインしたときに Jade が自分の通信（`jade:server_ping_v1`）を送ろうとして失敗し、仮のプレイヤーを使うテストが落ちる（仮のプレイヤーはその通信路を持たない）。Singulo の不具合ではないので、Jade を入れた全体の GameTest は流さず、連携の読み込みと表示だけを確かめる。WTHIT ではこの問題は起きない。

## 工場モニター（monitor/FactoryMonitor）

- 机のモニター（`FactoryMonitorBlock`。研究所の小物 `LabDecorBlock` を継いだ）を使うと、サーバーがまとめを作って送り（`MonitorPayload`、open）、クライアントが画面（`FactoryMonitorScreen`）を開く。開いている間、画面は毎秒まとめを頼む（`MonitorRequestPayload`）。サーバーは、モニターがあり、プレイヤーが8ブロック以内にいるときだけ答える。
- 範囲は16ブロック（立方体）。モニターから2ブロック以内のサーバーラック1台ごとに8広がる（4台まで、最大48）。
- 読み込まれているチャンクのブロックエンティティだけを見る（範囲のブロックを1つずつ調べない。チャンクを読み込まない）。
- 数える装置: 報告を出す装置と、報告のないマルチブロックのコントローラー（組みかけなら未形成として一覧に出す）・電力を持つ装置（電力の量だけ）。マルチブロックの部品（コントローラーと二重になる）・ケーブル・パイプ・クリエイティブの電源は数えない。GameTest で、組みかけのペンローズ炉・ジェット鍛造炉・創世炉が一覧に出ることを確かめる。
- 発電・消費・蓄電は数えた装置の合計。止まっている装置は「手を入れたほうがよい」状態（`State.stalled`: 注意・電力不足・出口がいっぱい・未形成）で、待機と電源を切った装置は入れない。近い順に64台まで。ドローンはステーションの枠ごとの状態を、運搬中・待機中（印刷中を含む）・困っている（メモリなし・キットなし・電力不足・上がふさがり）に数える。
- 画面（幅248、GUI の決まりの枠とヘッダー）: 電力の3つの窓、止まっている装置の一覧（6行、ホイールで送る。名前と理由は「…」で切り、ツールチップに全文と座標）、ドローンのまとめ（ツールチップにステーションごと）。持ち物欄はない（読むだけの画面）。
- GameTest `monitorListsStalledMachinesAndDrones`（ラックで広がる範囲、止まっている焼成炉、メモリのないステーション、送っても変わらないこと）。

## 銀河の性質（genesis/GalaxyTraits）

- 銀河ごとに種（long）と性質（int）を持つ。性質: 下の3ビットが形（渦巻・棒渦巻・楕円・環・不規則）、次の5ビットが腕の色（0 は種まかせ、1〜16 は染料の色+1）、その上の1ビットが大きな銀河。0 はそれまでの版と同じ。
- 夜空の銀河の保存（`GenesisGalaxies`）は、種の配列 `seeds` に並べて性質の配列 `traits` を足した。以前の保存は性質 0 として読む。送る（`GalaxyPayload`）ときも、種と同じ並びで性質を送る。
- 生まれる前（揺籃・種火・安定化）の核に素材を使うと性質が変わり、1個減る（同じ性質なら減らない）。染料・ブレイズロッド・スライムボール・エンダーアイ・マグマクリーム・ネザースター。
- 完成した炉にもう一度原初の種を使うと、種火からやり直す（作る物の登録と出来上がった物はそのまま。性質は 0 から選び直す）。やり直した炉はエピローグを出さない（`reborn` を保存）。
- 星の並べ方（`client/GalaxyDraw`）: 性質 0 の渦巻は、乱数を引く順番まで以前と同じにしたので、以前の銀河は同じに見える。染料の色は、種で腕の色を引いたあとに差し替える。棒渦巻は中心の棒の両端から2本の腕、楕円は厚みのある古い星の集まり、環は小さな核と明るい輪、不規則は星の生まれる塊。大きな銀河は夜空で1.5倍。
- 生まれかけの宇宙（核の上）・誕生の演出・完成した炉の上の銀河・画面の窓・エピローグも同じ性質で描く。画面の窓は、以前は画面だけの簡単な描き方だったのを、夜空と同じ星の並びから描くようにした。窓にカーソルを重ねると、今の性質と素材の使い方が出る。
- ハンドブックの創世炉の章に「銀河を選ぶ・増やす」を足した。
- GameTest `materialsShapeTheGalaxyAndSeedsMakeMore`（素材ごとの性質、以前の保存の読み込み、核に使ったときの減り方、完成した炉のやり直し）。

## ガラスの階段と水

- 水に浸かったガラスの階段（`GlassJoin.Stairs`。アンドロイドのガラスの階段も）は、バニラではブロック1つ分の水を描くので、透けるガラスの段の中まで水が見える。水はふつうの階段と同じに描き、ガラスの段の中には入っていないように見せる。`LiquidBlockRenderer.tesselate` の頭（`GlassStairsWaterMixin`）で、同じ描き方をもう一度呼んでバニラの水の面を受け取り（スレッドごとの印で、その間は素通り）、階段を 2×2×2 に分けた区画（`GlassJoin.filledOctants`）の平面で切り分けて、ガラスの区画にかかる部分を捨てる（`client/GlassStairsWater`）。水面の傾き・流れの絵・光はバニラのまま。
- バニラが描かない面を足す: 水とガラスの区画の境、ガラスの区画のすぐ外にある同じ水との境（隣の水は浸かった階段との境を描かない）、隣の水に浸かったガラスの階段の向かいの区画がガラスのときの境。どれもガラスの側へ向け、静かな水の絵で描く。
- Sodium を入れているときは Sodium が水を描くので、バニラと同じ見た目のまま。
- GameTest `glassStairsHoldWaterInTheOpenPart`（区画の分け方と、水が入ること）。

## ガラスのハーフブロック

- 模様のないガラス4種（ホワイトガラスパネル・黒色強化ガラス・アンドロイド透過ガラス・アンドロイド遮断ガラス）のハーフブロック（tools/building_variants.py の `GLASS_SLAB_BASES`。レシピは recipes.py の最後）。
- 階段とハーフブロックは `GlassJoin.Shaped`（元のガラス `base()`）。境目の決まりは階段と同じ: 元のガラスとの間は描かず、同じガラスの階段・ハーフブロックとの間は、相手の形にすき間なく覆われた面だけ描かない（`GlassJoin.covered`）。
- モデルは階段と同じく 1/8 の箱の集まりで、見える面ごとに形に沿った枠の絵（下付きと上付き。2つ重ねると元のガラスのモデル）。隣の同じガラスのブロックは、ハーフブロックに隠れていない 1/4 だけを描く（白・黒は `GlassJoinModel`、つながるアンドロイドのガラスは `ConnectedGlassModel` がハーフブロックも同じガラスの箱として扱う）。
- 階段・ハーフブロック自身の面も、同じガラスの階段・ハーフブロックに一部を覆われていれば、自分の形があって覆われていない 1/4 だけを、その組の枠の絵で描く（`GlassJoinModel` が階段・ハーフブロックのモデルも包む。階段の側面にハーフブロックが当たるときなど）。
- アンドロイド用は `AndroidGlassSlab`（ぶつかり方と道探しは階段と同じ。`AndroidPathing.glass`）。水に浸かったときの水の描き方も階段と同じ（`GlassStairsWater` は `Shaped` を見る）。
- GameTest `glassStairsHoldWaterInTheOpenPart` にハーフブロックの区画・種類・水を足した。建材の変種は40種（`variantsCopyTheirBaseAndAppearInNewStructures`）。

## 携帯型アンドロイド印刷機（android/PortableAndroidPrinterItem）

- 道具（重ねられない）。電力は、入れたメモリの型の1体分（メモリがなければ倍率1の型の 80,000 FE。メモリを替えて容量が減っても溜まった電力は消さない）（`ComponentEnergyStorage`、`SinguloComponents.ENERGY`。蓄電装置の充電の枠で充電）。中身は小型クリスタルメモリ・アンドロイドキット・自己修理キットのストック（1スタック）・アンドロイド用装甲板の4枠で（キットは1組16個まで）、アイテムの `DataComponents.CONTAINER` に持つ。
- 空中で右クリック: 画面（`PortablePrinterMenu`・`PortablePrinterScreen`。アンドロイドの配色で、メモリの型の色）。枠の中身は変わるたびに手の印刷機へ書き戻し、開いている間は手の印刷機を動かせない。印刷ボタンは目の前（2ブロック先、上下2段まで探す）の地面に置く。
- 地面の上面を右クリック: 準備ができていればそこに置く（できなければ画面を開く）。置ける所は、固い床の上で1×2ブロックが空いている所。
- 置くと、キット1つと組立ステーションの2倍の電力（`PRINT_FE` × `COST_FACTOR` 2 × 型の倍率。剣の型で 80,000 FE、満タンで1体分）を使い、手から離れて `PortablePrinterEntity` になる。ふたが開き（16 tick）、印刷面の上で印刷し（`RuinAndroid.PRINT_TICKS`）、アンドロイドが使った人の方へ1歩降り、ふたが閉じ（16 tick）、持ち物へ戻る（いない・いっぱいならその場に落とす。消されても落とす）。
- 印刷したアンドロイドは `makeGuard`（追従モード）のあと `loseStation` で、使った人の護衛の身寄りのないアンドロイドになる（組立ステーションでリンクし直せる）。自己修理キットのストックは、印刷したアンドロイドの枠に入るだけ持たせ、装甲板は積む（胸当てとして装備される）。持ち歩いている間（1秒ごと）は、16ブロック以内の自分の身寄りのないアンドロイドのキットが減っていれば、ストックから補充する（`inventoryTick`）。
- 描画（`PortablePrinterRenderer`）: 寝かせたカバン（殻・ふた・取っ手・印刷面のモデル）。ふたは後ろの縁を軸に110度開き、印刷面が殻の中からせり上がる。前（取っ手）は使った人の方を向く。印刷面の上面には、組立ステーションの上面と同じく動く絵（走査線が往復し、四隅の吐出口が順に光る）を重ねる。エンティティの絵は動かせないので、ブロックの絵 `block/portable_printer_bed`（16×16 のうち真ん中の 12×8 を使う。濃い印刷床が印刷面いっぱいで、縁の四隅が順に光る）をブロックの絵の束から描く。絵は tools/portable_printer.py（アイテムは黒鉛色のカバンに水色の継ぎ目。キットの白い箱と見分ける）。
- レシピは精密組立台（ホワイトセラミック複合材4・セラミック基板2・超伝導コイル2・基礎回路2・鋼板2）。
- GameTest `portablePrinterPrintsAFollowingOrphan`（メモリがないと印刷できない、置く、身寄りのない追従の護衛、キットと電力の減り、自己修理キットと装甲板の受け渡し、持ち物へ戻る）。
- Mk2（`portable_android_printer_2`、段階3の精密組立台で Mk1 から）: 組（メモリ・キット・自己修理キット・装甲板）を3つ積み、電力は3組の型の1体分ずつの合計。地面に置くたびに、次の組（`SinguloComponents.PRINTER_NEXT`）から順に、そろっている組で1体印刷し、次の組へ進む。画面は組ごとに1行で、行の左の印が次に印刷する組（▶。選んだがそろっていない組は枠だけ）。印を押すとその組を次に印刷する。ヘッダーに次に印刷する型。地面のカバンは、置いた印刷機の種類（同期する `ITEM`）で絵を選ぶ（Mk2 は継ぎ目が紫）。GameTest `portablePrinterMk2PrintsTheChosenSet`（選んだ組の型を印刷し、その組のキットを使い、そろっている次の組へ進む）。

## アンドロイドが落ちている物を拾い、預ける（android/RuinAndroid）

- 護衛のアンドロイドは、手が空いているとき（戦い・作業・預けに行く途中・戻る・充電でない）、8ブロック以内に落ちている物を拾いに行く（`CollectGoal`、預けに行くゴールと同じ優先度）。拾うのは、置かれてすぐでなく、プレイヤーが投げたのでない（`ItemEntity.getOwner()` がプレイヤーでない）、持ち物かバックパックに入る物。同じ物に重ね、残りを空いた枠へ。
- 最後に拾ってから3秒たつか持ち物がいっぱいになると、拾った分だけを自動で預ける。持ち主が手渡した分は、同じアイテムに重ねていても手元に残る。手動の「近くの箱へ預ける」では、持ち主が手渡した分も預ける。預け先がなければ、次に拾うか預け先の設定を変えるまで待つ。
- 預け先の種類: チェスト類（チェスト・樽・シュルカーボックス・ほかの MOD の chest/barrel/crate。まだ開けていない戦利品の箱は除く）と、作業（資材口と作業指令台。指令台は隣と、リンクした資材口の倉庫へ入れる）。設定でどちらを優先するか（なければもう一方）、または預けないかを選ぶ。範囲は「近くの箱へ預ける」と同じ（横12・上下4）。
- 設定はアンドロイドごとに保存（`collect`・`store`。以前のアンドロイドは、拾う・チェスト優先）。装備のページの、並べ替え・預けるボタンの下に2つのボタン（拾う: 磁石、押し込みでオン。預け先: 箱・指令台の画面・赤い斜線の箱）。説明はツールチップ。
- GameTest `androidsCollectDropsAndStoreThemInAChest`・`androidsKeepPickupsWhenStoringIsOffAndSkipThrownItems`・`androidAutoStashKeepsEditedCargoAfterReload`。

## 精密組立台の手組み（recipe/MachineRecipe・machine/MachineBlockEntity）

- 組立盤は5×5から四隅を除いた21マス（`assembly_grid` に保存）。各マスには素材の通常のスタック上限まで置け、1回の組み立てに各マスから1個ずつ使う。触媒は盤の外の専用枠（マガジン）、使い終わった触媒は専用の出力枠。外の面からは材料を入れられず、製品と使い終わった触媒だけを取り出せる。
- レシピの `shape` は5文字×5行で、文字は `ingredients` の番号（A, B, ...）、空白は何も置かないマス。四隅は空けておく。`shape` を持てるのは、復元品も質量もない精密組立台のレシピだけ。`shape` のない（データパックの）レシピは、配置順を問わず、材料の必要個数と同じ数のマスを使う。
- 配置の元は `tools/assembly_shapes.py`、エディターで保存した配置と材料は `tools/assembly_edits/`（[編集手順](../development/README.md#精密組立台のレシピを編集する)）。どの配置図もちょうど1つの製品に当たることを GameTest `everyInstalledAssemblyDiagramMatchesExactlyOneProduct` で、構造部品のレシピがその設備のフレームを使うことを `tools/test_multiblock_recipes.py` で確かめる。
- 2回分のレシピ（`*_pair`）: 縮退圧縮炉・C空洞・縮退熱炉のフレームと鏡面プレート。右上と左下に1組ずつ置き、触媒は1個。
- JEI の＋ボタンは1回分、Shift＋クリックは入る回数分を盤に並べ、押し出した部品は持ち物へ戻す（`MachineRecipeTransfer`）。アンドロイドは加工カードの個数を1回分の配置に直して置く（`android/work/AndroidAssembly`）。盤が使用中か材料が足りないときは、材料を手元に残す。
- 以前の保存（`slot_layout` がない）: 加工の進み具合は捨て、10枠の材料は画面を開いた人の持ち物へ入るだけ戻す。残りは次に開いたときに戻すか、壊したときに落とす。触媒とオーバークロックチップは同じ枠に残る。GameTest `assemblerRecoversLegacyInputsAndDropsAllRemainingContents`。
- 待機の理由: 配置が違うときは「配置を確認」（`misplaced`）。触媒だけが足りない盤は、できる製品の名前を出す。

## ハンドブックの図（client/HandbookVisual・client/HandbookBlueprint）

- ページごとの図は `tools/guide_visuals.py` で決め、`guide/chapters.json` の `visuals` に書き出す。代表アイコン（`TOPIC_ICONS`。全ページ必須）、行き先（`ROUTES`）、操作の見出し（`ACTION_TITLES`）、レシピの図（`DIAGRAMS`）、説明（`CAPTIONS`）、構造（`BLUEPRINTS`。ホロ投影機と同じ設計図ID）。
- 構造の図は既定の大きさの設計図を上から見た段ごとの図で、コントローラーの段から開き、＋−で段を移る。段ごとにブロックと個数の一覧を出す。
- 見せる範囲: 章とページは段階（`CHAPTER_STAGES`・`PAGE_STAGES`）と発見（`CHAPTER_DISCOVERIES`・`PAGE_DISCOVERIES`。進捗、または `item/` で持ち物や見ているブロック）で開く。行き先は見えるページだけ出す。「次の目標」は、未達成のうちは序盤の技術目標（`STARTER_GOALS`）だけを出す。
- 電解槽の酸素の出力タンクには、焼成炉で使うと石炭が減るという案内を出す。
- `tools/test_handbook_visuals.py`: 発見の条件が実在の進捗を指し、伏せたページが最初の本に出ないこと。全ページのアイコン・行き先・図が解決できること。鋼鉄の比較の図が加工機と作業台のレシピに合うこと。
