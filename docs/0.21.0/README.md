# 0.21.0: 装置の様子・工場モニター・銀河のやりこみ

[変更履歴](../curseforge/changelog-0.21.0.md)

## 装置の様子の報告（machine/MachineReport）

- 1台の装置の様子を1つの報告にまとめる: 状態（画面の状態の記号 `Panel.Status` と同じ7つ）・短い言葉（画面のヘッダーと同じ翻訳キー）・理由の続き・進み具合・蓄電・使う/作る電力（FE/t）・装填中の触媒と残り・マルチブロックの足りない部品と、空けておく所をふさぐブロックの数。
- 報告を出す装置（`MachineReport.Source`）: 加工機とマルチブロックのコントローラー（`MachineBlockEntity`。待機中は `MachineDiagnosis` で理由を出す）・触媒装置（`CatalystDeviceBlockEntity`。発電機は作っている電力）・熱電発電機・専用の画面を持つ大型の装置（ペンローズ炉の炉心制御装置・降着ジェット鍛造炉・創世炉・ワームホール生成器・懸濁貯留槽などの宇宙の装置。画面のヘッダーと同じ分け方）。ほかの装置は電力の量だけ（Jade・WTHIT は自分で電力を出すので、行は出ない）。
- `MachineReport.of(level, pos)`: マルチブロックの部品ならコントローラーの報告。組み上がっていないマルチブロックのコントローラーには足りない部品を付け、状態を未形成にする（置いた直後の装置は、まだ状態を求めていないため）。大きさを選べる形は、足りない数がいちばん少ない大きさで数える。数え方はホロ投影機のチャットの報告と同じ（`HoloProjectorItem.shortfall` に分けた）。
- NBT で送る（理由の行は、文字だけの行と飾りのある行で NBT の型が違うので、1行ずつ包んで並べる）。
- GameTest `reportsExplainIdleMachinesAndMissingParts`（土を入れた焼成炉の理由、未形成の縮退圧縮炉の足りない部品の数、送っても変わらないこと）。

## Jade・WTHIT（compat/jade・compat/wthit）

- どちらも任意の連携。本体の jar の API でコンパイルし（`maven.modrinth:jade`・`maven.modrinth:wthit`、版は gradle.properties）、開発中の起動には `-PwithJade`・`-PwithWthit` を付けたときだけ入れる（WTHIT は Bad Packets も入れる）。
- Jade: `@WailaPlugin` の `SinguloJadePlugin`。サーバーのデータはすべてのブロックに登録し、`shouldRequestData` で報告を出す装置・マルチブロックの部品とコントローラーだけに絞る（見るたびにサーバーへ頼むため）。部品にはブロックエンティティがないが、ブロックのクラスで頼めるので、部品を見てもコントローラーの様子が出る。
- WTHIT: `waila_plugins.json` の `singulo:machine`（common と client）。WTHIT はブロックエンティティのあるブロックにだけデータを頼むので、部品を見ても出ない。設定の切り替え `singulo:machine`。
- 両方の連携が読み込まれることを `runGameTestServer -PwithJade`・`-PwithWthit` のログで確かめた。表示はクライアントで確認する。
- `-PwithJade` で GameTest を全部流すと、仮のプレイヤーがログインしたときに Jade が自分の通信（`jade:server_ping_v1`）を送ろうとして失敗し、仮のプレイヤーを使うテストが落ちる（仮のプレイヤーはその通信路を持たない）。Singulo の不具合ではないので、Jade を入れた全体の GameTest は流さず、連携の読み込みと表示だけを確かめる。WTHIT ではこの問題は起きない。

## 工場モニター（monitor/FactoryMonitor）

- 机のモニター（`FactoryMonitorBlock`。研究所の小物 `LabDecorBlock` を継いだ）を使うと、サーバーがまとめを作って送り（`MonitorPayload`、open）、クライアントが画面（`FactoryMonitorScreen`）を開く。開いている間、画面は毎秒まとめを頼む（`MonitorRequestPayload`）。サーバーは、モニターがあり、プレイヤーが8ブロック以内にいるときだけ答える。
- 範囲は16ブロック（立方体）。モニターから2ブロック以内のサーバーラック1台ごとに8広がる（4台まで、最大48）。
- 読み込まれているチャンクのブロックエンティティだけを見る（範囲のブロックを1つずつ調べない。チャンクを読み込まない）。
- 数える装置: 報告を出す装置と、報告のないマルチブロックのコントローラー（組みかけなら未形成として一覧に出す）・電力を持つ装置（電力の量だけ）。マルチブロックの部品（コントローラーと二重になる）・ケーブル・パイプ・クリエイティブの電源は数えない。GameTest で、組みかけのペンローズ炉・ジェット鍛造炉・創世炉が一覧に出ることを確かめる。
- 発電・消費・蓄電は数えた装置の合計。止まっている装置は「手を入れたほうがよい」状態（`State.stalled`: 注意・電力不足・出口がいっぱい・未形成）で、待機と電源を切った装置は入れない。近い順に64台まで。ドローンはステーションの枠ごとの状態を、運搬中・待機中（印刷中を含む）・困っている（メモリなし・キットなし・電力不足・上がふさがり）に数える。
- 画面（幅248、GUI の決まりの枠とヘッダー）: 電力の3つの窓、止まっている装置の一覧（6行、ホイールで送る。名前と理由は「…」で切り、ツールチップに全文と座標）、ドローンのまとめ（ツールチップにステーションごと）。持ち物欄はない（読むだけの画面）。
- GameTest `monitorListsStalledMachinesAndDrones`（ラックで広がる範囲、止まっている焼成炉、メモリのないステーション、送っても変わらないこと）。

## 銀河の性質（genesis/GalaxyTraits）

- 銀河ごとに種（long）と性質（int）を持つ。性質: 下の3ビットが形（渦巻・棒渦巻・楕円・環・不規則）、次の5ビットが腕の色（0 は種まかせ、1〜16 は染料の色+1）、その上の1ビットが大きな銀河。0 はそれまでの版と同じ。
- 夜空の銀河の保存（`GenesisGalaxies`）は、種の配列 `seeds` に並べて性質の配列 `traits` を足した。以前の保存は性質 0 として読む。送る（`GalaxyPayload`）ときも、種と同じ並びで性質を送る。
- 生まれる前（揺籃・種火・安定化）の核に素材を使うと性質が変わり、1個減る（同じ性質なら減らない）。染料・ブレイズロッド・スライムボール・エンダーアイ・マグマクリーム・ネザースター。
- 完成した炉にもう一度原初の種を使うと、種火からやり直す（作る物の登録と出来上がった物はそのまま。性質は 0 から選び直す）。やり直した炉はエピローグを出さない（`reborn` を保存）。
- 星の並べ方（`client/GalaxyDraw`）: 性質 0 の渦巻は、乱数を引く順番まで以前と同じにしたので、以前の銀河は同じに見える。染料の色は、種で腕の色を引いたあとに差し替える。棒渦巻は中心の棒の両端から2本の腕、楕円は厚みのある古い星の集まり、環は小さな核と明るい輪、不規則は星の生まれる塊。大きな銀河は夜空で1.5倍。
- 生まれかけの宇宙（核の上）・誕生の演出・完成した炉の上の銀河・画面の窓・エピローグも同じ性質で描く。画面の窓は、以前は画面だけの簡単な描き方だったのを、夜空と同じ星の並びから描くようにした。窓にカーソルを重ねると、今の性質と素材の使い方が出る。
- ハンドブックの創世炉の章に「銀河を選ぶ・増やす」を足した。
- GameTest `materialsShapeTheGalaxyAndSeedsMakeMore`（素材ごとの性質、以前の保存の読み込み、核に使ったときの減り方、完成した炉のやり直し）。
