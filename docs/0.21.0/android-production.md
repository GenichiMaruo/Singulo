# アンドロイドの製作と全品目の取得経路

Minecraft 1.21.1、NeoForge、Singulo 0.21.0の通常構成で、登録アイテム504品目と読み込まれたSinguloのレシピ514件を照合した。405品目がレシピの成果物または副産物に含まれる。残る99品目の中には専用設備で生産する物、遺構で回収する物、内部処理用の見本がある。Mekanismを追加すると、ガスタンクとガス・液体兼用タンクのアップグレードが精密組立台の製作対象に加わる。

## 確認した範囲

| 対象 | 件数 | 検査内容 |
|---|---:|---|
| 作業台 | 208 | 実際の材料から指令台で記録し、注文計画とアンドロイドの製作処理を実行。完成品の数・コンポーネント・返却物を照合 |
| 加工機械 | 262件・18種類 | 通常機械16種・254件はカードを記録し、アンドロイドが選ぶ搬入面へ工具・材料・液体を投入。実機を1サイクル運転し、搬出面から回収した全製品の数・液量・コンポーネントを照合。潮汐紡績機6件と降着ジェット鍛造炉2件はアンドロイドの加工処理を使い、実際の投入から完成品の回収まで確認。Mekanism入りでは通常機械が256件、合計264件 |
| かまど・溶鉱炉 | 4 | アンドロイドが材料を投入し、燃料を入れた実際の炉で焼き、完成品を回収 |
| 石切台 | 40 | 40件すべての成果物に、作業台で製作を確認した経路がある |

依存関係の調査では、実行時のアイテムタグとレシピの材料、加工機の種類、液体、修復対象、副産物を照合した。バニラ素材、探索で得る原本・設計図、ボスや自然現象からの回収品を用意できる前提で、通常構成の全レシピに材料を供給する経路があった。判定単位は品目の種類。実機で一連の工程を動かした例には、溶岩クラフト、ビスマスの精製、電解、フードプリンター、かまど・溶鉱炉がある。

## 液体を使う注文

作業台のレシピカードには通常どおり中身入りのバケツを記録する。作業指令台またはリンクした資材口に、取り出し可能な面を向けてタンクを隣接させ、液体を運べるタンクアップグレードをアンドロイドに装着する。作業台の実際のレシピがその材料欄に空のバケツを返す場合、バケツ1個分を対応する液体1,000 mBで賄える。実バケツを使った欄だけ空バケツが残る。魚や追加データを持つバケツは現物が必要。

実注文の検査では、溶岩バケツ1個と外部タンクの溶岩2,000 mBから3回製作し、空バケツが1個戻った。待機中の個体にだけ溶岩1,250 mBを入れた検査では、その個体が1回製作し、手元に250 mB残った。個体の液体を使う注文には、必要な量を運べる個体を割り当てる。外部の供給元を限定した注文には、その供給元の制限が適用される。

## 専用設備の操作

- 銅精製カードからビスマスを注文すると、触媒反応器で副産物のビスマスを回収し、同時にできた銅を在庫へ戻す。電解の酸素も注文対象にできる。サーバーの機械レシピから記録したカードでは、同じ注文の後の工程で確定副産物を使う場合、原料は1回分で済む。
- フードプリンターは加工カードの完成品に合わせて料理を選ぶ。印刷には食材から得るペースト、カートリッジ、電力を用意する。
- 冷却塔には水や溶岩と冷媒の液体窒素を同時に搬入できる。縮退圧縮炉は炉殻ブロック1回分の材料4種類を同時に受け入れる。
- 精密組立台の後期6レシピは200,000 FE/tを使う。標準容量は100,000 FEのため、容量アップグレードMk1以上と十分な給電が要る。加工カードは使用回数のある工具を機械に残し、次の加工にも使う。修理で最大寿命や修理回数が変わる工具は、修理対象の状態をカードに記録する。
- ワームホールの口は生成器が対ごとに識別情報を付ける。アンドロイドは、その情報を保ったまま固定化装置に運んで納品する。
- RGB染色台の色指定と染色ボタン、創世炉への最初の種の投入と合成対象の登録はプレイヤー操作。創世炉は登録後に生産したアイテムを搬出できる。
- ハロー捕集器は稼働中の炉心の近くで暗黒物質を連続生産する。探査やボスの報酬、加速器でまれに得る磁気単極子は、必要数を入手して資材口へ供給すると後続の注文に使える。

## 大きな注文の処理量

以前はP工程の注文を組み立てる際、各工程で先行する全工程を調べていた。上限の1,024工程では523,776組を比較する。修正後は完成品の種類から先行工程を引く。材料を厳密一致で指定した直列の注文なら、工程数にほぼ比例する。タグで代替素材を認める工程は先行する完成品の種類も調べる。多数の工程が同じ中間素材を生み、後続工程がそれらすべてを待つ配置では、記録する依存関係自体が工程数の二乗に比例し得る。この数値はコード上の比較回数で、tick時間の実測値は[大規模施設の負荷測定](server-scaling.md)を参照。

共有在庫だけで組める注文は1回の計画で決まる。液体が足りず、個体が持つ液体も調べる場合は、その液体を持つ待機個体ごとに計画を試す。たとえば該当する100体のどれも必要量を持たない場合、注文の見積もり1回で共有在庫の計画1回と個体別の計画が最大100回発生する。
