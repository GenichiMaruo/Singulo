# ドローン輸送 設計メモ

0.14.0 で追加するドローン輸送の仕様と実装方針。プレイヤー向けの説明は実装が固まってから `docs/player/` とハンドブックに書く。

## 決定事項

| 項目 | 決定 |
|---|---|
| リンク | 持ち主ごとの自動ネットワーク。同じディメンションで、同じ持ち主の発着ポートがすべて行き先に並ぶ |
| メモリの入手 | 遺構の警備機ドックの一波を全滅させたとき、確率（40%）でドックの上に出る。型はドックの段階で決まる（1 ローター・2 ジェット・3 反重力） |
| 射程 | 箱のバッテリー容量で決まる。梱包箱 160・バッテリー付き 760・大容量 3,160 ブロック |
| 印刷台の見た目 | アンドロイド組立ステーションと同じ筐体・同じ顔つきのバイザーの系統。顔はドローン用（丸い単眼とローターの印）、上面は着陸パッド、光の色は橙で、ひと目で区別できる |

## 構成

| 要素 | ID | 内容 |
|---|---|---|
| ドローン用クリスタルメモリ | `drone_memory` | アンドロイド用より小さいチップ。ステーションに入れる（減らない） |
| ドローンキット | `drone_kit` | 印刷1回につき1つ使う |
| ドローン・ステーション | `drone_station` | メモリ・キット・生産アップグレード（3機まで）・シールド許可証。印刷 20,000 FE。ドローンは上空で待機する |
| ドローン発着ポート | `drone_port` | 空き箱・荷物9・着荷箱3・受け取り9。行き先を選んで発送する |
| 梱包箱 3種 | `packing_crate` ほか | 空き箱は重なる。梱包済みの箱は中身を持つアイテム（シュルカーボックスと同じ部品） |
| 輸送ドローン | `cargo_drone` | プレイヤーやモブの攻撃では傷つかない |

## 電力

- 発送に要る電力 = 2,000 FE + 直線距離 × 50 FE/ブロック。梱包のときにポートが支払う。
- 射程 = (箱の容量 − 2,000) ÷ 50。箱は電力をためない（支払った電力はその便で使い切る）ので、電力が増えることも消えることもない。
- ステーションの電力は印刷だけに使う。ドローンの往復の電力はかからない。

## 流れとアニメーション

1. 発送: 行き先を選んで「発送」を押すと、荷物と空き箱1つを梱包して「積み込み待ち」に置き、電力を払う。荷物はここで固定され、取り消すと元の欄に戻る（電力も戻す）。
2. 呼び出し: 積み込み待ちのポートは、半径64ブロック以内の読み込まれた同じ持ち主のステーションから、待機中のドローンを呼ぶ。
3. 積み込み（ポートが時間を進める。ドローンは真上で静止）: 開扉 0–10 tick → 昇降台が箱を持ち上げる 10–25 → 爪で掴む 25–33（33で受け渡し）→ 台が下がり扉が閉じる 33–48。
4. 巡航: 発着点の高さと、途中の読み込まれた地形の高さより上を飛ぶ。上昇 → 水平 → 降下。
5. 荷降ろし: 開扉 → 空の台が上がる → 爪を開く（33で受け渡し）→ 箱を載せた台が下がり扉が閉じる。
6. 帰還: ステーションの上の待機位置へ戻る。

着荷した箱は着荷箱の欄に入り、受け取り欄に少しずつ開梱される。空になった箱は空き箱の欄へ移る（いっぱいなら着荷箱の欄に残る）。着荷箱の欄に空きがないと、ドローンは真上で待つ。荷物を地面に落とすことはない。

## 荷物の保全

- 荷物の正は常にどこか1か所にある: ポートの積み込み待ち → 飛行の記録（ワールドの保存データ `DroneFlights`）→ 着いたポートの着荷箱。ドローンの実体は記録を表示して動かすだけで、荷物を持たない。
- ドローンが読み込み範囲の外に出る（チャンクの読み込みが外れる）と、記録は「見えない飛行」になり、時間で進む。行き先が読み込まれていれば手前でドローンを出して着陸の演出をし、読み込まれていなければポートが読み込まれたときに直接受け取る。
- 古い実体が後で読み込まれても、記録と食い違えば消える（荷物は記録の側にあるので増えない）。
- 行き先のポートが壊されていれば発送元へ戻す。どちらもなければ、梱包済みの箱をその場に落とす（中身は箱の中に残る）。
- ポートを壊すと、積み込み待ちと着荷箱は梱包済みの箱のまま落ちる。

## 実装の状況（段階1）

| 範囲 | 場所 |
|---|---|
| 本体 | `src/main/java/.../drone/`（`DroneNetwork`・`DronePortBlockEntity`・`DroneStationBlockEntity`・`CargoDrone`・`DroneCrateItem`・メニュー） |
| 描画・画面 | `client/CargoDroneRenderer`・`DronePortRenderer`・`DroneStationScreen`・`DronePortScreen` |
| 絵・モデル | `tools/drones.py`（正面の単眼・着陸パッド・昇降口・梱包箱・メモリ・キット・ドローンのテクスチャ）、`tools/shapes.py` の昇降口のくぼみ |
| レシピ | `tools/recipes.py` の末尾。ステーション・ポート・梱包箱3種は作業台の定形、キットは精密組立台 |

メモリの条件は、出撃した一波の全機がプレイヤーに倒されたこと（チャンクの読み込みが外れて見失っただけでは出ない）。

### 2回目の調整（ゲーム内確認のあと）

- **自動搬出**: ポートは加工装置と同じ `SideConfig`（面ごとの入出力・自動排出・全体スイッチ）を持ち、右レールの設定から同じ窓で変える。排出するのは受け取りの欄と、着荷箱の欄に残った空の箱。ホッパーやパイプも面の設定に従う。`SideConfigPayload` は `SideConfig.Holder` を実装したブロックエンティティならどれでも受け付ける。
- **輸送の進み**: ポートの画面の真ん中に、出る便・来る便を4行まで（段階と、飛行中の進みのバー）。進みは見えている間はドローンが水平の距離から書き、見えない間は時刻から決める。
- **発送の条件**: そのポートを受け持つドローン（半径64ブロックのステーションの、待機中か運搬中のドローン）がいなければ発送できない。全機が運搬中なら、箱は積み込み待ちになる。
- **連続の仕事**: 荷物を届け終えて帰りかけのドローンは、近くの積み込み待ちのポートへそのまま向かう（便の記録を使い直す）。待機中のドローンより近ければ、そちらが選ばれる。
- **解体**: ステーションの画面の行の×を2回押すと、待機中のドローンがステーションに降りて分解され、キットが欄へ戻る。その枠は止まり、＋でまた印刷する。
- **扉**: 真ん中の合わせ目から外側の縁を軸に上へ跳ね上がり、立ちきってから壁ぎわを下へ引っ込む。閉じるときはその逆。
- **ローター**: 厚さ0の板は両面が同じ位置に描かれてちらつくので、裏を描かない薄い箱の羽根と、回転の残像のうすい円盤にした。

見た目（ドローンのモデル・昇降口の動き・各画面）は、ゲーム内で確認してから確定する。

### 3回目の調整（通り道と位相透過）

- **通り道**: ドローンは壁や天井を抜けない（`DroneRoute`）。行き先が近い（水平32ブロック以内）なら出発点から目的地まで空いているマスをたどる道を探し、遠ければ出発点から空の見える所（その列のいちばん高いブロックより上）まで出る道と、目的地から空へ出る道を探して、その間は途中の地形（1ブロックごと）より4ブロック上を巡航する。A*（6方向と水平の斜め。斜めは両わきが空いているときだけ）で、探す範囲は各方向40マス・16,000マスまで。読み込まれていない所は探さない（読み込まない）。見通しのきく点は飛ばしてなめらかにする。
- 道が見つからないと、ドローンはその場で待って2秒ごとに探し直し、ポートの輸送中のページに「経路なし」と出る（荷物は便の記録の側にあるので失われない）。
- 見えない飛行から出てくるときは、空の見える高さに出してから、道を探して降りる。
- **位相透過アップグレード**（段階3・精密組立台）: ステーションの右レールの強化の段（加工装置のアップグレードと同じ場所）に入れると、そのステーションのドローンは壁を抜けて、目的地の少し上へまっすぐ近道する。ドローンの箱か、進む向きに1.4ブロック先までがブロックに重なると、壁を抜けている間とその前後（抜け終えて0.4秒）に紫の光をまとう。光る姿は奥行きを比べずに描くので壁越しに見え、紫の粒と専用の音が出る。
- **着荷箱の重なり**: 空になった箱が空き箱の欄に入らない（別の段階の箱・満杯）ときは、着荷箱の欄の同じ空の箱に重ねて、次の荷物のための欄を空ける。

### 4回目の調整（型と高さ）

- **許可証とアップグレード**: ドローン・ステーションとアンドロイド組立ステーションの両方で、シールド許可証を右レールの強化の段へ出し、位相透過アップグレードを枠の中（生産アップグレードの下）へ入れた。
- **積み込みの光**: 位相透過の光の見通しは今の目的地までにした（降りる先のポートを壁と取り違えて光らない）。
- **高さ**: 巡航は1ブロックごとに、葉を除く地面＋3ブロックと葉の上＋1ブロックの高いほうを、前後3ブロックのいちばん高い所に合わせる（高い所の手前から上がる。森の上で高くなりすぎない）。見えない飛行から出てくるのは、目的地の3ブロック上か地面の3ブロック上の高いほう。道を探すときは、下に3マスの空きがないマスへの1歩を遠回りに数えるので、地面すれすれを飛ぶのは戸口などそこしか道がないときだけ。
- **巡航の速さ**: 巡航の点は数ブロックおきなので、次の点までではなく、巡航が続く所の終わりまでの道のりで速さを絞る（速い型が速く飛べる）。
- **型**（`DroneKind`）: ステーションは入れたメモリの型で印刷し、枠ごとに型を覚える（メモリを替えても印刷済みのドローンはそのまま）。便の記録も型を持ち、見えない飛行の時間も型の速さで決まる。

| 型 | メモリ | ドック | 速さ | 見た目と効果 | 音 |
|---|---|---|---|---|---|
| ローター | `drone_memory` | どこでも | ×1.0 | 白い胴と橙の帯、4つのローター、4本の爪。進む向きへ前に傾く | `drone.rotor` |
| ジェット | `drone_memory_jet` | 段階2以上 | ×1.6 | 黒鉛色の細い胴に青い線、後退翼、外へ開いた2枚の尾翼、2つのエンジン。青白い炎（速いほど長い）。曲がる向きへ横に傾き、上るときは機首を上げる。腹の横棒の爪で箱をはさむ | `drone.jet` |
| 反重力 | `drone_memory_gravity` | 段階3（まれ） | ×1.25 | 頂点を上にした暗い結晶の核と八角形の光輪、4つの浮かぶビット。箱を持つとビットが四隅の上で止まって牽引の光を当て、箱を青緑の場で包む。空のときは足もとに場の輪が広がる | `drone.hover` |

モデルは `CargoDroneRenderer` の `RotorModel`・`JetModel`・`GravityModel`、絵は `tools/drones.py` の `PARTS`・`JET_PARTS`・`GRAVITY_PARTS`。検査は `jetDroneDeliversFaster`・`stationPrintsTheKindOfItsMemory`・`upperKindsDropOnlyFromUpperFacilities`。

### 5回目の調整（入手と段階）

- **ドローンのレシピ**: すべて段階2で作れる。大容量バッテリー付き梱包箱は量子もつれ素子の代わりにダイヤモンド、位相透過アップグレードはアメジストの欠片を使う。
- **メモリの入手**（`DroneKind.memoryChance`・`rollMemory`）: ドックの段階は施設で決まる（地表観測拠点1・研究棟2・封鎖培養施設と地下アンドロイド研究所3）。上の型は上位の施設からだけ出る。地下研究所はドックが多いので、上位ほど確率を下げる。

| ドックの段階 | 一波を倒して出る確率 | ローター | ジェット | 反重力 |
|---|---|---|---|---|
| 1 | 40% | 100% | — | — |
| 2 | 35% | 65% | 35% | — |
| 3 | 25% | 40% | 40% | 20% |

- **マルチブロックの構成ブロック**（`tools/recipes.py` の `TIER_GATED`）: コントローラと同じ段階の鍵の素材を少しだけ使う。ボスを倒して段階を上げるまで、上位の構成ブロックは作れない。
  - 段階2（粒子加速器）: 加速管に超伝導線材（2本で1つ）。冷却塔は、コントローラも構成ブロックも段階1の素材なので変えない。
  - 段階4（縮退圧縮炉・C空洞・縮退熱炉）: BE凝縮触媒の寿命の 1/48（精密組立台の触媒枠。レーザー冷却器が要る = 研究棟の残響の番人の投影核）。
  - 段階5（Pリアクター・シールド・Tシリンダー・ワームホール生成器・創世炉）: 時間結晶触媒の寿命の 1/48（時間結晶育成槽が要る = 封鎖培養施設の重力の澱の縮退核）。炉殻ブロックは時間結晶モジュール1つ（24個ぶん）。光格子基板と鋼板を使う3つ（シールド発生塔本体・ワームホール生成器外殻・Tシリンダー時間結晶ホルダー）は、時間結晶モジュールのレシピがそれらの途中と見なされないよう、触媒の代わりに時間結晶モジュール1つ（本体と外殻は材料と個数を2倍）。
  - レシピの選び方の検査で「ほかのレシピの途中になる」例に使っていたTシリンダー軸受は、鍵が入って途中にならなくなったので、トロイダル磁気コイルに替えた。

## 段階

1. 基礎（今回）: 上の要素すべて、近距離・遠距離の輸送、アニメーション、保全、GameTest。
2. 連携: 作業指令台の資材口・納品先にポートを使う、登録注文で遠隔の在庫を保つ、手順カードの「発送」。
3. 拡張: 自動発送のきまり（○個たまったら・○秒ごと・信号で）、取り寄せリクエスト、公開ポスト、空き箱の返送、呼び出し端末、測量メガネでの航路表示、チャンネル名で網を分ける、数値のサーバー設定化。

## アンドロイド連携

資材口・納品口との隣接接続と、空き箱の面別搬出を実装。[接続方法と検証](android-drone-integration.md)を参照。
