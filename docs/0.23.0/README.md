# 0.23.0

開発中のバージョン。

## 地表観測拠点の周りの地面をならす（singulo:graded）

地表観測拠点は jigsaw の型紙を `beard_thin` で地面に合わせて置くが、斜面では箱の上の地面を削りきれない。型紙で何も置かないマス（八角形の建物の四隅や、外壁の外の縁の上）には元の地面が残り、建物の欠けた所に土が盛られたように見えていた。

0.23.0 から、`worldgen/structure/observation_post.json` は jigsaw を `singulo:graded`（`ruin/GradedStructure`）で包む。置いたあと（`afterPlace`）に、各チャンクで次の高さより上にある自然の地面（`#minecraft:overworld_carver_replaceables` のうち液体でないもの）を取り除く。

- 型紙の箱の中と、箱のすぐ外の1列: 床（型紙のいちばん下の段）の1段下。
- その先: 箱からの水平距離（切り上げ）1マスごとに1段高い斜面。範囲は箱から12マスまで（地形の調整のある構造物が置かれるチャンクの範囲と同じ）。

型紙のブロック・水には触れない。取り除いた列の上に土が出たら、取り除いた中でいちばん上にあった表面のブロック（草ブロック・ポドゾルなど）に戻す。それより急な山では、12マス先に段差が残る。

すでに生成されたチャンクは変わらない。生成ファイルは `tools/gen_data.py` の `graded()` から作る。確認は `RuinGameTests.gradedRuinClearsGroundAroundBuilding`。

## 旧遺構の再構築

施設再構築装置は、銅ブロック・ダイヤモンド・精密アクチュエーター・クリスタルメモリでクラフトできる。旧版で生成され、通常ボスを倒して保管庫の封鎖が解けている施設の起動ブロックに使う。クリエイティブでは撃破前にも使えるが、戦闘中と警報中は対象外で、保管庫は封鎖されたままになる。地表観測拠点は対象外。最初に上書き範囲と警告を表示し、30秒以内に同じ装置で同じブロックをスニークしながら再クリックすると実行する。

実行前にワールドをバックアップし、建造物・収納・貴重品を退避する。範囲の地形、ブロック、建造物、収納は上書きされ、取り消せない。初期設定では、シングルプレイのワールド所有者とサーバー管理者だけが実行でき、対象範囲のチャンクがすべて読み込み済みで、ほかのプレイヤーが範囲内にいない必要がある。消費した場所は再利用できない。処理中断時の地形ロールバックはない。

旧施設の保管庫の中身と再生履歴は引き継ぐ。地下アンドロイド研究所では、保存されている部屋・通路・立坑の配置を基に現行の部品で置き直す。通常の4施設は起動ブロックの座標と元の向きを保ち、現行の施設を置く。旧施設の範囲が新施設より広い部分は取り除かない。

`config/singulo-server.toml` の `[facilityReconstruction]` で変更できる。変更後はワールドを開き直す（専用サーバーは再起動）。

```toml
[facilityReconstruction]
recipeEnabled = true
multiplayerAccess = "admins_only"
```

`recipeEnabled = false` は新規クラフトだけを禁止し、すでに入手した装置はこの設定では無効にならない。マルチプレイ（専用サーバーまたはLAN公開中）は `admins_only`（管理者のみ）、`everyone`（全員）、`disabled`（管理者も含め禁止）から選ぶ。LAN未公開のシングルプレイにはこの権限設定は適用されない。

## 放電型アンドロイド「エクレール」

覚醒したエルゴ球の大蛇（沈んだ炉心区画）を倒すと、25%の確率で「小型クリスタルメモリ（放電型）」が手に入る。抽選は参加人数にかかわらず撃破ごとに1回。当たると、大蛇の残骸から放電が走り、その場にメモリが1個残る（`ErgosphereLeviathan.dropSparkMemory`）。アンドロイド組立ステーションにこのメモリを入れてエクレールを印刷する。どこで手に入るかは、ハンドブック・JEI・説明欄には載せない。

### 位置づけ（AndroidKind.SPARK）

- シエル・ルージュと同じ隠し型。`Origin.HIDDEN`・印刷の電力3倍。遺構の印刷台と研究所の試作機には出ない。
- `spark_android_spawn_egg` と `android_memory_spark` は `SinguloItems.HIDDEN`。メモリの名前は紫（`EPIC`）。
- 強み: バックパック内蔵、内蔵バッテリー1個（充電の満タン1.5倍）、作業1.5倍速。体力30・装甲5。
- 役割は中距離の多対一。一体への火力はシエル・ルージュより低いが、放電が敵から敵へ連鎖する。この型だけの強みは、近くの仲間への給電。

### 見た目

- 濃い鋼灰色の髪に、電光の黄色のインナーカラー。光の色はレモン寄りの白黄（`ACCENT = 0xF4F25A`）。配色は `tools/androids.py` の `spark_android`。
- 背中の腰に蓄電・発電の機械を背負う（模型の `spark_unit` に取り付け、`client/SparkGear` で描く）。白い外殻に暗い芯、中央にコイルの窓、左右に蓄電セルとケーブルの口がある。
- 両腕に、コイルの帯を3本巻いた白い放電籠手を着ける。拳の先に電極が出ている。
- 腰の機械の左右の口から、同じ側の籠手の肘へケーブルがたるんでつながる。戦闘中や連携中は、電流の光の粒が機械から籠手へ流れる。
- 追加のバッテリーはスカートの後ろに下げず、腰の機械に収める。蓄電セルは、内蔵の1本と追加の数だけ灯る。
- 設計メモリはアニメーションつき（`spark_memory`）。枝分かれした電光が結晶を2回続けて走り、そのたびに結晶が瞬く。

### 技

| 状態 | 内容 |
|---|---|
| `STATE_ARC` | 8ブロック以内の敵へ、指先から放電する（5）。4.5ブロック以内の別の敵へ最大3体まで跳び移り、跳ぶたびに0.7倍。壁の向こうへは跳ばない |
| `STATE_PALM` | 2.4ブロック以内の前の敵に左の掌を当て（7）、押し返す |
| `STATE_FIELD` | 片膝を落として床に掌を当て、半径4ブロックの電場を4秒張る。中の敵に0.5秒ごとに2のダメージと鈍化。張ったあとも戦い続ける |
| `STATE_TENRAI_CHARGE` → `STRIKE` | 大技「天雷」。両腕を掲げて頭上に電荷を溜め（36 tick）、半径10ブロックの見えている敵すべて（近い順に最大8体）へ放電を落とす（14） |
| `STATE_PLAY` | 待機中、右手を顔の前に上げ、指先ではじける火花を眺める（4秒） |

ふだんは敵から4〜7ブロックの間合いを保つ。天雷の溜めでは、体の継ぎ目に電光の筋が胸から手足へ浮き出て、不規則に瞬く（`spark_android_surge_{0,1,2}.png`。刀型と同じ作り方）。同時に髪が逆立ち、頭上の電荷の玉へ両手から細い放電が昇る。放電はブロックを壊さず、火を付けず、バニラの雷も使わない。

### 給電と連携

- **給電**: 2秒ごとに、8ブロック以内にいる同じ持ち主のアンドロイドのうち、充電が6割未満で最も少ない1体へ、自分の満タンの2%を分ける。自分は5割を残す。分けた分だけ自分が減り、電力の合計は変わらない。
- **シエルとの電磁加速**: 同じ持ち主のシエルが10ブロック以内でレールガンを組み上げ始めると、電力80を使って注ぎ足す。溜めが8 tick短くなり、光線のダメージが1.25倍、色が電光の白黄になる。ルージュとの交差照準で発射の時を合わせている間は、加速しない。
- **ルージュの刀への電荷**: 同じ持ち主のルージュが10ブロック以内で紅一閃を構えると、構えの前半のうちに電力80を使って刀に電荷を与える。残心の遅延斬撃が4増え、駆け抜けの通り道と斬った相手に放電が走る。
- 連携中は、腰の機械から相手へ放電の線がつながって見える。

### 効果音

`tools/sounds/recipes.py` の放電型の節で作る（字幕は5言語）。`spark_arc`・`spark_palm`・`spark_field`・`spark_tenrai_charge`・`spark_tenrai_strike`・`spark_supply`・`spark_link`・`spark_play`、大蛇の `memory_discharge`。

### 検査

`src/gameTest/java/.../android/SparkGameTests.java`:

- 隠し型であること（一覧に出さない・紫・印刷倍率が刀型と同じ）と、内蔵バックパック・充電1.5倍・作業1.5倍速
- アークが近くの敵へ跳び移り、跳ぶたびに弱まること。遠すぎる敵と壁の向こうの敵には跳ばない
- 掌底放電が前の敵だけに当たって押し返すこと
- 電場が中の敵だけを削って鈍らせ、時間で消えること
- 天雷が範囲の見えている敵すべてに落ち、壁の向こうには落ちないこと
- AI つきで天雷の溜めから落雷まで進み、アークを放つこと
- 給電で電力の合計が変わらないこと。自分が5割以下のときと、仲間が満ちているときは分けない
- 電磁加速でシエルの溜めが短くなること。刀への電荷でルージュの遅延斬撃が強くなること
- 大蛇の抽選の境界（25%）と、残ったメモリを組立ステーションが放電型と認識すること

模型・装備・放電の見た目は、ゲーム内で確認する。

## アンドロイド用無線充電器 Mk2・Mk3

無線充電器に上位版を2つ足した（`AndroidChargerItem.Tier`）。どれも持ち歩くと、充電の切れたアンドロイドが寄ってきて充電する。持ち物にいくつあっても、電力の残っているいちばん上の段を使う。

| | Mk1 | Mk2 | Mk3 |
|---|---|---|---|
| 段階・材料 | 2 | 3（Mk1・量子もつれ素子2・超伝導コイル2・ニホニウム板2） | 5（Mk2・コラプサー・インゴット2・SMESモジュール・エキゾチック物質2） |
| 蓄えられる電力 | 300,000 FE（満充電30回分） | 1,500,000 FE（150回分） | 8,000,000 FE（800回分） |
| 充電の速さ | 5秒で満タン | 2倍 | 4倍 |
| 充電できる距離 | 4ブロック | 8ブロック | 16ブロック |
| 1回の右クリックでブロックから受け取る量 | 100,000 FE | 500,000 FE | 2,500,000 FE |

Mk3 は、16ブロック以内にいる自分の護衛のアンドロイドのうち、充電が半分を切ったものへ0.5秒ごとに給電する。アンドロイドは作業や戦闘を止めない。給電するのは持ち物の最初の Mk3 だけなので、何個持っても速くならない。

充電器から受け取る電力は、満タンを超える分を取らない（`RuinAndroid.receiveWireless`）。使った電力より多く充電が増えることもない。

アイコンは携帯端末の形（`tools/androids.py` の `charger_icon`）。縦長の本体に画面と残量の目盛り、下に送電の格子、上にアンテナがある。段が上がるほど目盛りとアンテナが増え、Mk1 は水色、Mk2 は菫で光る。Mk3 は黒いコラプサーの筐体に橙で光り、両側面に光の帯が走る。

確認は `ChargerGameTests`。段ごとの性能、いちばん上の段を使うこと、Mk3 の給電が自分のアンドロイドだけに届いて電力を増やさないこと、満タンで止まることを検証する。

## アンドロイド用装甲板 Mk2・Mk3

装甲板に上位版を2つ足した（`AndroidArmorPlateItem.Tier`）。どれも護衛のアンドロイドの装甲板の枠に1枚積むと、胸当てとして働く。上位版は前の世代の装甲板を芯にして精密組立台で作る。材料にした装甲板のエンチャント・名前・金床での修理の費用を引き継ぐ（`MachineRecipe` の上位版の表。無線充電器の上位版も、同じ表で蓄えた電力を引き継ぐ）。

| | Mk1 | Mk2 | Mk3 |
|---|---|---|---|
| 段階・材料 | 2 | 3（Mk1・ニホニウム板4・超伝導コイル2・量子もつれ素子） | 5（Mk2・コラプサー・インゴット2・コラプサー内張り2・縮退核） |
| 防御・防具強度 | +8・+2 | +10・+4 | +12・+6 |
| ノックバック耐性 | — | +0.1 | +0.25 |
| エンチャントのしやすさ | 15 | 18 | 22 |

- Mk3 は燃えない（溶岩に落としても消えない）。
- 防具のエンチャントの対象（`#minecraft:enchantable/armor`・`chest_armor`）に、どの段も入れてある。
- 体に着けたときの装甲の部品（胸と左肩）は、どの段も Mk1 と同じ。
- Mk2・Mk3 では、体の一部を少し外側から、透けて光るエネルギーシールドの殻で覆う（描画の `ArmorShield`）。頭は覆わない。
  - 殻は部位ごとに、その部位の動きに合わせて描く（体全体を拡大して重ねると、手足ほどずれるため）。
  - 模様がゆっくり流れる（チャージ状態のクリーパーと同じ描き方）。
  - Mk2 は胴と両肩（上腕）を覆う。Mk3 はさらに前腕・腰・太ももまで覆う。
  - Mk2 は菫の六角の格子（`android_shield_hex.png`）。
  - Mk3 はコラプサーの橙で、降着円盤のような斜めの光の筋（`android_shield_collapsar.png`）。
  - ふだんはかすかに脈打ち、攻撃を受けた瞬間に明るく瞬く。
  - 模様は `tools/androids.py` の `shield_hex`・`shield_collapsar` で作る。上下左右につながるので、流れても継ぎ目が出ない。
- エンチャントの光沢も、装甲の部品に重なる。
- アイコンは Mk1 と同じ胸当ての形で、色を変えてある。Mk2 は青い鋼に菫の発光ラインと肩の鋲、Mk3 は黒に橙の発光ラインと、肩と裾の筋。

確認は `MachineResultGameTests` の `armorPlateUpgradesKeepEnchantments` と `chargerUpgradeKeepsStoredPower`。実際の精密組立台で一段ずつ組み、エンチャント・名前・電力が引き継がれることを検証する。

## 武装モジュール

護衛のアンドロイドの画面の「状態」のページで、装甲板の右に武装モジュールの枠を1つ足した。修理キット・装甲板・武装モジュールが同じ間隔で並ぶ。この枠は持ち物の最後（`RuinAndroid.SLOT_WEAPON`）にあるので、既存のアンドロイドの持ち物の並びは変わらない。積んだモジュールはアンドロイドの利き手の装備に写すので、ドロップ増加はふつうの仕組みのまま効く。

技のダメージは型ごとに決まった値を直接与えていて、攻撃力の属性は使っていない。そこで、護衛のアンドロイドが与えるダメージをダメージのイベントの1か所で受け、モジュールの効果をかける（`AndroidWeaponModules`）。全型の全技に同じように効く。

| モジュール | 段階 | 効果 |
|---|---|---|
| 出力増幅器 | 2 | すべての技 ×1.3 |
| 出力増幅器（Mk2） | 3 | ×1.6（Mk1 から作り、エンチャントを引き継ぐ） |
| 出力増幅器（Mk3） | 5 | ×2.0（Mk2 とコラプサー・インゴットから。燃えない） |
| 重撃モジュール | 4 | 大技 ×2.2（ほかの技はそのまま） |
| 連撃モジュール | 4 | 技の待ち時間 ×0.75 |
| 吸収モジュール | 3 | 与えたダメージの1割だけ体力が戻る |
| 貫通モジュール | 3 | 相手の防具の守りを4割無視する |
| 凍結モジュール | 3 | 当てた相手を2秒鈍らせる（鈍化 II） |
| 対番人モジュール | 4 | ボスと戦うようになり、ボスへ ×1.8（下を参照） |

- 出力増幅器だけに、剣のエンチャントを付けられる（`#minecraft:enchantable/sword`）。効くのは、ダメージ増加・アンデッド特効・虫特効、火属性、ノックバック、ドロップ増加。アンドロイドの攻撃全体にかかる。
- 特化モジュールは出力増幅器（Mk1）から精密組立台で作り替える。特化モジュールにはエンチャントを付けられないので、材料の増幅器のエンチャントは消える。
- 護衛のアンドロイドは、もともとボス（番人・地平線の監視者・最後の記録者と、その取り巻き）と互いに敵対しない。対番人モジュールを積んだ護衛だけがボスと戦う（`RuinAndroid.bossHunter`）。
  - ボスを狙い、技を当て、ボスの攻撃と、叩きつけ・投げ飛ばしの落下ダメージも受ける。
  - ボスの側は、どの護衛にも狙いを移さない（ボスの技はプレイヤーを狙う前提のため）。
  - ボスの強さの調整と報酬は、これまでどおりプレイヤーの人数で決まる。
- 重撃の「大技」は次の技。
  - 光刃型の回転斬り・斬撃波
  - 鞭型の叩きつけ
  - 光剣型の溜め突き・斬撃波
  - 斧型の叩きつけ・跳躍
  - レールガン
  - 紅一閃の駆け抜けと遅延斬撃
  - 天雷
- 連撃は、各型の戦いの目標が技の待ち時間を減らす所（`rapidCooldown`）で、3 tick に1回もう1つ減らす。
- アイコンは小さな基板の箱で、型の色で光る記号が入る。出力増幅器は段の数だけ山形が付き、Mk3 は黒い枠。

確認は `WeaponModuleGameTests`（枠と利き手の装備・ドロップ増加、出力増幅器の倍率とダメージ増加、重撃・吸収・凍結・貫通・対番人・連撃）と、`MachineResultGameTests.amplifierUpgradeKeepsEnchantments`。

### 印刷機の武装モジュールの枠

- **組立ステーション**: 左の列の「補充」の右に、武装モジュールの枠を1つ足した（`AndroidStationBlockEntity.SLOT_WEAPON`。古い保存と番号がずれないよう、最後に置く）。印刷したアンドロイドがまだモジュールを積んでいなければ、この枠のモジュールを積む。印刷し直すアンドロイドは、預かっていた持ち物のモジュールをそのまま持つ。
- **携帯型アンドロイド印刷機**: 各行の装甲板の右に、武装モジュールの枠を組ごとに1つ足した。印刷すると、その組のモジュールを積む。
  - 中身の並びでは、組の4枠の並びのうしろに組ごとの枠を置く（`weaponSlot(組の数, 組)`）。既存の印刷機の中身はずれない。
  - Mk1 から Mk2 を作ると、Mk1 の枠にあったモジュールは Mk2 の1組目の枠へ移る（`moveWeaponsAfterUpgrade`）。
  - 印刷ボタンは、枠のぶんだけ右へ寄せて少し細くした。

確認は `WeaponModuleGameTests` の `stationFitsWeaponModuleOnPrint` と `portablePrinterFitsWeaponModulePerUnit`。

## パネルの階段・ハーフブロックと、コラプサー強化パネル

### 面の絵

これまでの階段・ハーフブロックは、元のブロックの絵をそのまま貼っていた。そのため、半分の高さの側面や階段の L 字の面では、縁取りと四隅の鋲が途中で切れていた。

0.23.0 から、見える面ごとに、その面の形に沿って描いた専用の絵を貼る。作り方は、ガラスの階段・ハーフブロックと同じ（`tools/building_variants.py` の `panel_face_texture`）。

- 外周には元の絵と同じ縁と明暗の線（上・左が明るく、下・右が暗い）を描き、出っぱった角から3画素内に鋲を置く。
- 幅8画素の所では、両側の鋲を1つにまとめる。
- 黒色強化パネルは、角から内へ補強の筋を入れる。
- 面いっぱいの面（ハーフブロックの天面・底面など）には、元の絵をそのまま使う。
- 絵は形と一緒に回す（状態の uvlock を使わない）。

### 一部が隠れた面の絵

パネル（白・黒・コラプサー）のブロック・階段・ハーフブロック・重ねハーフブロックについて、となりの不透明なハーフブロック・階段に一部だけ覆われる面は、隠れずに見える所だけを、その形に沿った縁の絵で描く（`client/PanelJoinModel`）。

- 作り方はガラスの `GlassJoinModel` と同じで、面を 1/4 ずつに分け、隠れた所は描かない。
- 絵は、見える 1/4 の組ごとの `<パネル>_join_<bits>`（`panel_join_textures`）。
- 隣が透けるもの（ガラスの階段など）のときは、覆われた所も透けて見えるので、元のまま描く。
- ガラス（ホワイトガラスパネル・黒色強化ガラスと、模様入りのアンドロイド用ガラス）の面も、不透明なハーフブロック・階段（パネルなど）に一部だけ覆われるときは、同じく見える所だけを枠の絵で描く（`GlassJoinModel` が `PanelJoinModel.coverage` を使う）。

### コラプサー強化パネル

黒色強化パネル8枚の輪の真ん中にコラプサー・インゴットを置くと、8枚できる（段階5）。階段・ハーフブロック・塀も、元のブロックと同じ作り方で作る。レシピは一覧の番号がずれないよう `recipes.py` の最後で足す（`building_variants.LATE_BASES`）。

- 爆発への強さは岩盤なみ（3,600,000）。
- タグ `minecraft:wither_immune`・`dragon_immune` に入れたので、ウィザーとエンダードラゴンに壊されない。
- ダイヤ以上のツルハシで、黒曜石なみに時間をかけて掘る（硬さ 50）。
- 絵は、紫がかった黒の装甲板に補強の筋、真ん中の芯と四隅の鋲が橙（`blocks_extra.collapsar_reinforced_panel`）。

### 発光コラプサー強化パネルとコラプサー強化ガラス

- **発光コラプサー強化パネル**: コラプサー強化パネル8枚の輪の真ん中にグロウストーンダストを置くと、8枚できる。明るさ15。硬さ・爆発への強さ・ウィザーとドラゴンへの強さ・掘る道具は、コラプサー強化パネルと同じ。絵は、コラプサーの枠と橙の鋲の中に、橙を帯びた白い光の面。
- **四芒星コラプサー強化ガラス**: コラプサー強化ガラス8枚の輪の真ん中にネザー水晶を置くと、8枚できる（四芒星黒色強化ガラスと同じ作り方）。強さはコラプサー強化ガラスと同じ。紫の四芒星の中心に橙の光。四芒星黒色強化ガラスと同じく、階段・ハーフブロックはない。
- **コラプサー強化ガラス**: 黒色強化ガラス8枚の輪の真ん中にコラプサー・インゴットを置くと、8枚できる。強さはコラプサー強化パネルと同じ。
  - 階段・ハーフブロックがある（`building_variants.LATE_GLASS_BASES`）。
  - 元のガラス・同じガラスの階段・ハーフブロックとの境目は描かない（`GlassJoin`）。
  - となりのハーフブロック・階段に一部隠れた面は、見える所だけを枠の絵で描く（`GlassJoinModel`）。
  - ハーフブロックは、白・黒のガラスのハーフブロックと同じマスに上下で重ねられる（`MixedGlassSlab.Collapsar`、ブロック `mixed_collapsar_glass_slab`、状態 `collapsar_on_top`・`other`）。
    - 白と黒の組は、これまでどおり `mixed_glass_slab`（状態 `black_on_top`）。0.21.0 から保存されている状態なので変えない。
    - 置き方・落とす物・狙った方に合わせる掘る速さと音・爆発で狙われた方だけが壊れる決まりは、白黒の重ねハーフブロックと同じ。
    - コラプサーを含むと、ウィザーとエンダードラゴンに壊されない。
- 重ねハーフブロック（ガラス・パネルとも）は、道具が上下どちらのハーフブロックも掘れるときだけ落とす（`canHarvestBlock`）。コラプサーの方を含むときは、ダイヤ以上のツルハシが要る。

### パネルの重ねハーフブロック

白いパネル・黒色強化パネル・コラプサー強化パネルのハーフブロックは、違う2つなら同じマスへ上下で重ねられる（`MixedPanelSlab`。状態は `lower`・`upper`。ガラスの `MixedGlassSlab` と同じ決まり）。

- どちらが上でも置ける。重ねたブロックにアイテムはない。
- コラプサーのハーフブロックを含むと、ウィザーとエンダードラゴンに壊されない（`canEntityDestroy`）。
- 壊すと、両方のハーフブロックが1つずつ落ちる。
- 次の3つは、狙った方のハーフブロックに合わせる。
  - ブロックの選択（ホイールクリック）
  - 掘る速さ
  - 音
- 爆発への強さは、爆発の中心の高さの方に合わせる。
- 鉄のツルハシで掘れる。
- 同じ色どうしは、これまでどおりふつうの2枚重ね（元のブロック）になる。

確認は `MixedPanelSlabGameTests`（白黒の重ね置き、コラプサーとの重ね置きと、ウィザー・ドラゴン・爆発・掘る道具）。

### 違う種類のガラスの間の面

この作品のガラスは、アンドロイド用のガラスを除き、種類が違っても同じガラスのように扱い、接する面を描かない（`GlassJoin.inFamily`）。対象は、白・黒・コラプサーのガラス、四芒星のガラス、遺構のガラス、研究所のガラスと、その階段・ハーフブロック・重ねハーフブロック。

- 一部だけ覆う形（ハーフブロックの横など）の面は、覆われない所が見えるので描く。
  - 白・黒・コラプサーのガラスと四芒星のガラスは、見える所だけを枠の絵で描く。
  - 遺構・研究所のガラスは、元の絵のまま描く。
- 四芒星・遺構・研究所のガラスは、これまでのふつうの透けるブロックから、境目を消すガラス（`GlassJoin.Glass`）に替えた。硬さ・強さ・保存されるデータは同じ。
- アンドロイド用のガラスは、つながって見える模様と、アンドロイドの通り抜けがあるので、これまでどおり同じ種類どうしだけをつなぐ。

確認は `GlassFamilyGameTests`。白黒の重ねハーフブロックの試験（`MixedGlassSlabGameTests`）も、白黒を入れ替えた重ねハーフブロックとの間を描かない決まりに合わせた。

## カバーの枠にガラスをはめる

カバーの枠に、ガラスもはめ込めるようにした（カバーの状態 `cover=glass`）。対象は、1ブロックいっぱいの透けるブロック（バニラのガラス・色付きガラス・遮光ガラスと、この作品のガラス）。板ガラスや、ガラスの階段・ハーフブロックは、すき間があるのではめ込めない。

- 枠と、中のケーブル・パイプを描いたまま、ガラスの板を足す（`CoverModel`）。
  - 板は、枠の棒（太さ2ドット）の内側の 12×12 ドットに縮め、1ドット奥に置く。枠の外側の面とは重ならない。
  - 絵は、ガラスの中央の 12×12 ドットを使う。
- 流れるときのケーブル・パイプの光も、ガラス越しに見える。
- 光を通し、隣の面を隠さない。窒息もしない。
- 当たり判定は、枠だけのときと同じ中空の箱で、外からは1ブロックいっぱい。
- 壊す速さ・音・爆発への強さは、はめ込んだガラスに合わせる。
- 外すときは、ブロックと同じく、ガラス、枠の順に外れる。
- 状態の値を1つ足しただけなので、これまでの保存データはそのまま読める。

確認は `ConduitCoverGameTests.coverTakesGlassAndStaysSeeThrough`。

### 光るブロックをはめたカバー

グロウストーンやシーランタンのような光るブロックをカバーにはめ込むと、そのブロックと同じ明るさで光るようにした。これまでは、見た目だけがそのブロックで、光らなかった。

- 明るさは場所ごとに違うので、状態では決まらない。電線・パイプのブロックは、ブロック・ガラス入りのときに `hasDynamicLightEmission` を返し、`getLightEmission` で場所ごとの明るさを返す。
- 明るさは、NeoForge のチャンクの補助の明るさ（`AuxiliaryLightManager`）に置く（`ConduitCover.updateLight`）。
  - 光の計算は別スレッドで、ブロックエンティティを読めないため。
  - チャンクと一緒に保存され、クライアントにも送られる。
- はめ込むとき・外すときに書き直し、光を計算し直す。はめ込み中（次の tick まで）はまだ光らない。
- 0.23.0 より前にはめ込んだ光るブロックも、ブロックエンティティを読み込んだとき（`onLoad`）に明るさを書くので光る。

確認は `ConduitCoverGameTests.glowingInlayLightsTheCover`。

### はめ込んだブロックの、ウィザーなどへの耐性

ブロックやガラスを入れたカバーは、はめ込んだブロックのウィザー・エンダードラゴンへの耐性も持つようにした（`ConduitCover.canEntityDestroy`。電線・パイプのブロックの `canEntityDestroy` から呼ぶ）。たとえばコラプサー強化パネルやコラプサー強化ガラスを入れたカバーは、次のどれにも壊されない。

- ウィザーの体当たり
- ウィザーの頭蓋骨
- エンダードラゴン

- 青いウィザーの頭蓋骨は、壊せるブロックの爆発への強さを 0.8 まで下げる。これも同じ答えで決まるので、耐性のあるブロックを入れたカバーは下がらない。
- 爆発への強さ・掘る速さは、これまでどおり、はめ込んだブロックのもの。
- 枠だけのカバーと、耐性のないブロックを入れたカバーは、これまでどおり壊される。

確認は `ConduitCoverGameTests.inlayLendsItsWitherProofing`。

### 道具の要るブロックは、適した道具でないと外せない

黒曜石やコラプサー強化パネルのように、掘るのに道具の要るブロックをはめ込んだカバーは、それを掘れる道具でないと外せないようにした（`ConduitCover.locked`）。

- 適した道具でなく壊しても何も外れず、行動バーに `message.singulo.cover.needs_tool` を出す。ケーブルも残る。
- 移設レンチはその道具ではないので、次のどちらでも外れない。
  - 移設モードのスニーク右クリック（1つずつ外す）
  - 撤去モード（ケーブルごと外す。続きのケーブルをまとめて外すときは、そのカバーだけ残す）
- 創造モードと、道具の要らないブロック（木材・ガラスなど）・枠だけは、これまでどおり外せる。
- 案内の「カバーの枠」の頁に、道具が要ることと、はめ込んだブロックの強さ（爆発・ウィザー・エンダードラゴン）がカバーにも付くことを足した（5言語）。

確認は `ConduitCoverGameTests.toolBoundInlayNeedsTheRightTool`。

### ガラスとパネルのハーフブロックを重ねる

白・黒・コラプサーのガラスのハーフブロックと、白・黒・コラプサーのパネルのハーフブロックを、同じマスに上下で重ねられるようにした（`mixed_panel_glass_slab`、`MixedPanelGlassSlab`。状態は `glass`・`panel`・`glass_on_top`）。

- 置き方はほかの重ねハーフブロックと同じ。どちらを先に置いても、どちらが上でもよい。アイテムはなく、壊すと両方のハーフブロックが1つずつ落ちる。
- 次の3つは、狙った方のハーフブロックに合わせる。爆発への強さは、爆発の中心の高さの方に合わせる。
  - ブロックの選択（ホイールクリック）
  - 掘る速さ
  - 音
- 掘って落とすのは、道具が両方を掘れるときだけ。
- コラプサーのハーフブロックを含むと、ウィザーとエンダードラゴンに壊されない。
- 同じ種類どうし（ガラスとガラス、パネルとパネル）は、これまでどおりの重ねハーフブロックになる。

見た目:

- 模型は、ガラスの半分（透ける描き方）とパネルの半分（不透明）を multipart で重ねる。描き方が違うので、1つの模型にはできない。
- ガラスの、パネルに接する面は描かない。パネルの、ガラスに接する面は、ガラス越しに見えるので描く。
- 半分が透けるので、隣の面を隠さない（`noOcclusion`）。
- 自分の面は、上下の半分ごとに隣に隠れるかを見る（`halfHidden`）。
  - ガラスの半分は、この作品のガラスか不透明な物に覆われると隠れる。
  - パネルの半分は、不透明な物に覆われると隠れる。
  - 片方の半分だけが隠れる面は、`MixedPanelGlassModel` がその半分の面だけを描かない。
  - 半分の面が一部だけ隠れるとき（となりのガラスの階段など）は、ほかのガラス・パネルと同じく、見える 1/4 だけを、見える形に沿った枠の絵で描く。絵は、ガラスは `<ガラス>_join_<bits>`、パネルは `<パネル>_join_<bits>`。
- この作品のガラスの仲間（`GlassJoin.inFamily`）に入れたので、となりのガラスは、このブロックとの間の面を描かない。

確認は `MixedPanelGlassSlabGameTests`。

### となりのガラスに一部隠れる面の絵

となりの階段・ハーフブロックに一部隠れるガラスの面は、見える所の形に沿った枠の絵（`<ガラス>_join_<bits>`、`glass_join_textures`）を貼る。

- 枠の内側は、階段・ハーフブロックの面と同じ地の色だけにする。単体のときの補強の筋や四芒星は描かない。
  - フルブロックの 1/4 と、階段・ハーフブロックの 1/4 が、同じ見た目になる。
  - 四芒星のガラスにも、この枠の絵を作る。
- 対象は、白・黒・コラプサーのガラスと四芒星のガラス。
- 模様入りのアンドロイド用ガラスは、これまでどおり。

## ガラス越しのブラックホール

ブラックホール（重力レンズ）とカメラの間にガラスがあると、ブラックホールが見えなくなっていたのを直した。奥の景色を歪めてから、手前のガラスを描く。

- 原因: レンズはワールドを描き終えてから掛けていた。手前の物に隠れるかを奥行きで見るので、ガラスなどの透ける物が書いた奥行きが、壁のようにレンズを隠していた。
- 対策:
  - レンズは、透ける物を描く前に掛ける（`GravitationalLensing.beforeTranslucent`）。固体・ブロックエンティティ・エンティティを描いたあと、`GlowDepth` が固体だけの奥行きを写した直後に呼ぶ。
  - 手前のガラスは、そのあと歪んだ景色の上に描かれる（ガラスの色も枠もそのまま見える）。
  - 鍛造炉のジェットも、レンズとの前後の重ね方（奥のレンズ → ジェット → 手前のレンズ、`applyWithJets`）のまま、ここで一緒に描く。ジェットより奥のガラスは、ジェットの上に重なって描かれる（ジェットは奥行きを書かないため）。
  - 黒い影と降着円盤の所は、レンズがブラックホールの中心の奥行きを書く（`lensing.fsh` の `gl_FragDepth`）。ブラックホールより奥のガラスは、影や円盤の上に出ない。
- これまでどおりワールドを描き終えてから掛ける場合:
  - シェーダーパック使用時。
  - 手に持った杖のレンズ。ワールドを描き終えてから足すため。
- ブラックホールの奥にあるガラスのうち、影と円盤の外の歪みの範囲にある所は、歪まずに描かれる。
