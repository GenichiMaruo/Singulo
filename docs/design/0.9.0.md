## 0.9.0の内容（方針: 新コンテンツより、今あるものの完成度を上げる）

作者の通しプレイは、下の修正のあとに行う。

### 1. バックパックのティア（済）
- 3段階: バックパック（12枠・段階2）→ 強化バックパック（18枠・段階3）→ 大型バックパック（24枠・段階4）。上位は1つ下を材料にして精密組立台で作る。
- 既存の「バックパックアップグレード」は12枠になる。旧版で13枠目以降に入れた物は消さない（取り出しだけでき、作業には使わない）。
- 中身が収まる大きいバックパックへは、中身を出さずに付け替えられる。収まらないものへは付け替えられない。
- 射撃型の内蔵バックパックは24枠のまま。
- GameTest: backpackTiersSetCapacity。

### 2. バランスの見直し
- 伐採の充電（済）: 固定24 → 12＋原木1本ごとに2（小さな木で約22、大きなジャングルの木で200前後）。
- 机上の検証: 全レシピを原料・時間・電力に展開して段階ごとに比べた（作業用の解析スクリプト）。段階内で極端に浮いた物は見つからなかった
  （構造用の部品が安く、コントローラやコアが高いのは意図どおり）。アンドロイドの電力は段階2の発電量に比べて小さく、制約になっていない。
  これを変えるかは、通しプレイで「電力ではなく移動・在庫・装置が制約」という今の手触りが良いかを見て決める。
- 通しプレイで見てほしい所: 生産アップグレード（段階2で原料約120）と工場式印刷ユニットの重さ、大型バックパック（段階4）の重さ、ボスの人数補正。

### 3. アンドロイドの仕上げ（済）
- 止まっている理由を出す: ステーションの電力不足・たどり着けない・素材不足・守られたブロック・作業の範囲に対象がない・置き場がいっぱい。
  アンドロイドの画面の吹き出し（赤い字）、作業指令台の注文の詳細、測量メガネを掛けたときの頭の上の印に出る。10秒続かなければ消える。
- 不具合の修正: 充電中にステーションがなくなった護衛が、充電の状態のまま止まり続けていた。自分で充電する状態へ移る。
- GameTest: stallShowsStationOutOfPower。
- 持ち物があふれて足元に落ちないようにした（枠は全部使う方針のまま。決まった数の枠を空けておくのではなく、あふれるかを計算する）。
  - 計画: 1回ずつ作るあいだの持ち物を、素材の残り・できた物・残る物（バケツなど）・副産物（記録した数ずつ）・今持っている物で数え、
    一度も枠を超えない一番多い回数を選ぶ。前は副産物を1枠ずつ・採掘を2枠と決め打ちしていた（副産物が多いとあふれ、少ないと枠が余った）。
    まとめた作業では、前の工程の残る物と副産物も、あとの工程のあいだ持っている物として数える。続けて作るとき（chainJob）は、
    今持っている物も数える（前は空の持ち物として数えていた）。
  - 作業中: 採掘・伐採・収穫は一緒に出る物が前もって分からないので、壊す前に出る物を決めて、持ち物に収まるかを確かめる。
    収まらなければ壊さずに、ここまでの分で作業を終えて置きに戻る（足りない分はあとでまた集める）。
  - GameTest: planCountsByproductsExactly、miningNeverDropsWhenFull（確かめる処理を外すと落ちることも確認）。
- アンドロイド作業台の預かり箱（27枠）: 作った物が持ち物に入りきらなければ、足元に落とさずに預かり箱へ入れる（作者の報告: オークのフェンス50個で10個強を地面に落とした）。
  - 預けた物はその注文の素材置き場の物として予約し（作業台を受け渡し場所の1つにする）、あとの工程は作る前に預かり箱から持ち物へ戻し、
    残った完成品は納品のときに取りに来る。持ち物を置きに戻るとき（片付け）には預かり箱を使わない。
  - 取りに来られなくなった物（注文の取り消しなど）は右クリックで受け取れる。壊すと中身を落とす。保存しても消えない。
  - バニラの作業台には預かり箱がない（入りきらなければ今までどおり落ちる）。
  - 再現テスト（フェンス50個、どの板材でも作れるレシピ、バックパックの有無）は今の計画ではどれも落とさなかったので、作者の環境との違いは未確認。
  - GameTest: fiftyFences*NeverDrop（3件）、workbenchBufferCatchesOverflow、workbenchBufferIsKept。
- 作業の持ち物で、同じ物が半端なスタックに分かれたままになっていた（作者の見立て）。素材を使うと、前のスロットから順に減らすので、
  いくつものスロットに少しずつ残る。計画は「同じ物は1つのスタックにまとまる」として枠を数えるので、分かれた分だけ枠が足りずにあふれていた。
  入れる前・使ったあと・装置や納品口へ渡したあとに、同じ物の半端なスタックを前のスロットへまとめるようにした（GameTest: carryStacksSameItems）。
- 作っている途中で充電が切れると、充電切れと起動を繰り返して、作業も充電も進まなかった（作者の報告）。目的（Goal）の見直しは1tickおきなので、
  充電切れになった次のtickにも作業が呼ばれ、作る姿勢に戻して「動ける」状態にしていた（作る間隔ごとに、また充電切れ）。
  作業は、動けないとき（充電切れ・充電中・襲われている）には何もしないようにした。充電を優先し、満タンになってから続きをする
  （GameTest: craftingPausesToRecharge）。
- 未着手: 保存と再開（OSごと終了・チャンクの読込順の違い）の検証は、既存の GameTest 以上のことはしていない。

### 4. 説明と導線のリワーク（済）
- ハンドブック: 各段階の章の先頭に「段階Nの流れ」（やることの順番・次の段階の鍵・つまずきやすい所）。前の「段階N+1へ進むには」と置き換えた。
- アンドロイドの章に「はじめての作業注文」（パンを作らせる手順と注文の画面の検索）と「止まっているとき」を足した。
- 長いページ（遺構の番人・アップグレード・加工）を段落の切れ目で分けた。
- 「進み具合」の章は、次の目標がある段階から開き、各段階のページから「段階Nの流れ」へ飛べる。
- 説明欄: 長い説明（70字以上）の13件に要約を足した。説明書5言語にバックパックのティアと止まっている理由を足した。
