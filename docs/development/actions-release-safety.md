# Actions公開安全性の修正と0.15.1成果物の維持

2026-11-06。修正は各維持ブランチから分離した `fix/release-actions-1211` と `fix/release-actions-1201` に用意した。
既存のPR #60 / #61、製品ソース、版番号、準備済みJAR、タグ、リリース、条件付きタスクは変更していない。マージ・公開は未実施。

## 修正

- CurseForgeの `retry-attempts` を1に固定。不確実な応答後の自動再投稿を防ぎ、draft Releaseの予約による重複実行防止を維持する。
- 公開は対応する維持ブランチからの手動起動に限定。Actionを上流コミットへ固定し、checkout資格情報の保存とジョブ全体へのGH_TOKEN環境変数の配布をやめる。
- 成功CI、全ジョブ、タグ、実際に試験したマージツリーの一致を維持し、未マージ・分岐したタグと変更済みのタグ作業コピーを拒否する。
- 信頼済み検証コードが、検証済みタグのJavaテスト宣言・宣言件数を読み取る。現在のworkflow-refの件数や版を過去の成果物へ当てはめない。
- 1.20.1ではタグ内のPython検証コードの実行をなくし、信頼済みの検証器でJava 17、Minecraft/loader、版、モデル・資源形式、診断クラス混入を検査してからコピーする。
- Forge/NeoForgeのタグ・成果物の取り違え、失敗した・欠落した・別名のテスト、ツリーや対象が一致しない成果物は拒否する。安全性のための検査を省略したり、失敗を成功扱いにする変更はない。

## 既存CI成果物を再利用する取り込み順

**安全性修正を先に維持ブランチへ取り込むと、既存0.15.1 CIのツリーと後続マージのツリーが変わる。**
既存成果物を使う場合、条件付きリリースで次の順を守る必要がある。これは手順の記録であり、今回実行した操作ではない。

1. 公開条件を満たした時点で #60 / #61 のHEAD・差分・CI・競合を再確認する。
   現在の検証済みHEADは #60 `36cb8053043cf966a2a26422b274921b67c1e74a`、#61 `876027cc4e7127a6b18d58d079deeb3a8a3cdc0e`。
2. そのリリースPRだけをマージし、マージ後の**全ツリー**が実際の成功CIツリーと一致することを確認する。
   #60のrunは `42002407263`、treeは `8d4676b5efdc1dadefa70a9a811f48f91b1cb0b3`。
   #61のrunは `42002426072`、treeは `e1788080a16baf7d0efc2444e1c47fb868d10b04`。
3. そのコミットへ不変の `v0.15.1`、`v0.15.1-1.20.1F` / `v0.15.1-1.20.1N` タグを作成する。既存タグがあれば先に照合し、移動しない。
4. その後、今回の公開安全性修正を維持ブランチへ取り込む。リリースタグのソースは変えない。
5. 安全な現行workflow-refから、上の成功runとリリースタグを指定して公開する。
   公開用コードは現行維持ブランチ、JAR・版・テスト一覧はタグと成功CI、という役割を分ける。
   タグは維持ブランチの祖先なので新しい取り込み済み検査に合格し、過去のCI JARを再ビルドせず昇格できる。

0.15.1の準備を維持する間は0.16.0の #62 を先にマージしない。
別の変更や安全性修正が先に維持ブランチへ入った場合は、検査を緩めず、更新後のリリースPRをCIで再検証して正確な成果物を用意し直す。
安全な公開コードが維持ブランチへ統合されるまでは、条件付きタスクの公開待ちを解除しない。スケジュールや条件そのものは今回変更していない。

## 未実施・残る条件

公開サイトへの送信、workflow dispatchによる公開、タグ作成・移動、マージ、formal approve、条件付きタスクの変更は行っていない。
秘密値、請求、権限・ブランチ保護設定も変更していない。Actionsの請求ロックは別の運用上の障害であり、ローカル検査の成功をリモートCI成功とは扱わない。
公開前には公開済みファイル・draft Release・進行中workflow・receiptを再確認し、失敗や結果不明の送信を自動再試行しない。
