# 0.17.1: 鍛造炉のブラックホールがジェットの手前に出る

[変更履歴](../curseforge/changelog-0.17.1.md)

## 症状

稼働中の降着ジェット鍛造炉を排熱側（杯の側）から炉の軸に沿って見ると、炉心のブラックホール（影と降着円盤）が、カメラと炉心のあいだで光る排熱側のジェットの上に描かれていた。本来はジェットの奥に見えるはずのもの。

## 原因

- ジェットとビームの光（`GlowDepth.additive`）は、ワールドを描き終えたあとでまとめて足す。重力レンズ（`GravitationalLensing`）は「ジェットより奥のレンズ → ジェット → 手前のレンズ」の順に掛ける。
- 炉心のブラックホールは、自分のジェットごと歪めて見せるため、いつも「手前のレンズ」に入っていた（`GlowDepth.behindJet` が自分の炉のジェットを数えない）。そのため、カメラ側に伸びた自分のジェットより後に描かれ、その上に重なっていた。

## 直し方

- 炉ごとにジェットの光の入れ物を2つ持つ（`GlowDepth.JetGroup`。炉心から見てカメラと反対側の半分＝奥、カメラ側の半分＝手前）。
  - 炉心を通り軸に垂直な面で分ける。カメラ側の半分は炉心より手前にあり、光はブラックホールで曲がらない。奥の半分はこれまでどおり歪む。
  - 加工側: ジェット・収束リング・照射の光・素材の光・仕上げの光・ビーム止め。排熱側: ジェット・杯の熱の光。拘束コイルは、それぞれある側に入る。
  - 点火・降着円盤への流れ込み・形成の閃光・標識・場の光は、炉心のまわりにあるので、これまでどおり奥（レンズの前）。
- レンズは「ジェットより奥のレンズ → 炉に属さない光 → 遠い炉から順に（奥の光 → 炉心のレンズ → 手前の光）→ 手前のレンズ」の順に掛ける。一列に並んだ炉では、手前の炉のブラックホールが、奥の炉のジェットを正しく歪める。
- 炉の入れ物は使い回す（最初は小さく取り、足りなければ伸びる）。炉ごとにレンズを掛けるので、画面に映る炉の数だけ画面のコピーが増える。

## ゲーム内の確認: 奥のブラックホールが景色からずれる

- 上の直し方の最初の形では、炉に属さないレンズ（潮汐紡糸機・Pリアクターなど）を、炉心のレンズを全部掛けたあとにまとめて掛けていた。炉心より奥にある紡糸機のブラックホールは、炉心のレンズで歪んだ景色の上に、歪まない位置で描かれ、まわりのブロックとずれた。逆（紡糸機のレンズが奥の炉心を歪める）は正しかった。
- 0.17.0 までは全部のレンズを1回で奥から描いていたので起きなかった（この版の途中で入れた不具合）。
- 炉に属さない手前側のレンズは、遠い順に、その位置より手前で最初に出てくる炉心のレンズと同じ回に入れて掛ける。1回の中では奥から描くので、手前の炉心のレンズが奥のブラックホールを景色と一緒に歪める。どの炉心より手前のものは最後に掛ける。
- ジェットが手前にかかるレンズは、これまでどおり最初（ジェットより前）に掛ける。

## ゲーム内の確認: 収束リングの光がブロックとずれる

- レンズは、画面で歪みの球に重なる所のうち、球の手前の面（炉心までの距離 − 球の半径 5）より奥にあるものだけを歪める（`lensing.fsh` の深度の判定）。
- 最初の形では、収束リングの光も「炉心からカメラ側の半分か」で前後を決めていた。斜めから見ると、カメラ側のリングのブロックは球の手前の面より奥にあって歪むのに、リングの光は歪まないあとの組に入り、ブロックと別の所に見えた。反対側では、光の下の景色の深度で歪むかが決まっていた。
- リング（突き抜けの演出と稲妻を含む）・拘束コイル・杯の熱・ビーム止め・照射の光・素材の光・仕上げの光は、四角形ごとに最初の頂点のカメラからの距離で分ける（`DepthSplit`）。球の手前の面より奥ならレンズの前（ブロックと一緒に歪む）、手前ならレンズのあと。
- ジェットの筒は、これまでどおり炉心で半分に分ける（炉心のすぐそばのジェットを球の中として歪む側に入れると、最初の不具合のとおりブラックホールの影の下に隠れる）。

## Pリアクターのうなりが、音の読み込み直しで消える

- 言語の変更などで音の読み込み直しが入ると、鳴っている音は全部止まる。このとき音には「止めた」印が付かない。
- `BlackHoleAmbience` は印だけで鳴り終わりを見ていたので、まだ鳴っているものと思い、鳴らし直さなかった。音のエンジンで実際に鳴っているか（`isActive`）も見て、鳴っていなければ忘れて鳴らし直す。
- ほかのくり返し音（`MachineSounds`・`BossSounds`・`JetForgeEffects`）は、もとから鳴っているかを見ていた。

## 事象の地平線倉庫を空にしても「1」と表示される

- 倉庫の見た目の更新（`getUpdateTag`）は、中身があるときだけ見本と個数を書いていた。空になるとデータが空っぽになり、NeoForge はクライアントで空のデータを読まない（`onDataPacket`）。そのため最後に送った個数（最後の1個など）が残った。
- 個数はいつも送る（空なら 0 で、読む側が空に戻す）。
- 同じ作りだったアンドロイド作業台（上に見せる物）も、いつも印を送るようにした。ほかの装置の更新データは、空のときも必ず値を書いている。
- GameTest `vaultSendsEmptinessToClients`。
