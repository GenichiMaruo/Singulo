# 0.18.0: アンドロイドの装飾

[変更履歴](../curseforge/changelog-0.18.0.md)

## 装飾の枠を5つに

- `AndroidAccessoryItem` の部位: `HEAD=0`・`BACK=1`（首/背中）・`HAND=2`・`FACE=3`・`WAIST=4`（`PARTS=5`）。0.17 までの3枠の番号は変えず、顔と腰をうしろに足した。持ち物の装飾の枠（`RuinAndroid.SLOT_DECOR` から `DECOR_SLOTS=5`）も、持ち物の最後なので古い保存はそのまま読める。
- メガネは顔、腰リボンは腰へ。古い保存で枠に合わない装飾は、読み込んだときに、その装飾の枠が空いていれば移す（`RuinAndroid.moveDecorToItsPart`）。
- 画面（装飾のページ）: 体の並びに合わせて2列。左に上から頭・首/背中・腰、右に顔（頭のとなり）と手（腰のとなり）（`AndroidMenu.decorX/decorY`）。
- 描画（`AndroidRenderer.Accessories`）: 頭と顔は頭、首/背中は胴、腰は腰、手は左手の変形。帽子（ベレー帽・魔女の帽子・麦わら帽子）をかぶるとアホ毛をしまう。

## RGB染色台

- `dye/RgbDyeStationBlockEntity`・`RgbDyeStationMenu`・`client/RgbDyeStationScreen`。機械（`SimpleMachineBlock`）の仕組みで、正面は色の輪の絵（`tools/decor_content.py` の `rgb_front`）。
- 赤・緑・青・白・黒の染料の枠（タグ `c:dyes/*`）。毎 tick、入る分だけインクにする（染料1個 = 8目盛り、各色64目盛りまで）。
- 1回に使うインク（各色0〜4目盛り）: 白 = 3色の最小、黒 = 1 − 3色の最大、赤・緑・青 = それぞれ − 白。純色は色みだけ、灰色は白と黒だけ。
- 画面（幅212）: 左に色の輪（32×32 マス、1マス2ドット。中心ほど白）と明るさのつまみ（16段）、右上に染める物の枠（タグ minecraft:dyeable）・「染める」・色見本（重ねると #RRGGBB）、下に5色の染料の枠とインクの目盛り（1回に使う分の印つき）。
- 色を選ぶ・染めるは画面のボタンの番号で送る（`SET_COLOR | RGB`・`APPLY`）。選んだ色は台に保存し、画面には R・G・B の3つの値で送る。
- 壊すと、枠の物と、インクを染料に戻せる分（端数は失う）を落とす。
- レシピ: 上に赤・緑・青の染料、真ん中に白の染料・作業台・黒の染料、下に板材3。
- GameTest: `dyeStationCostFollowsTheColor`・`dyeStationTurnsDyesIntoInkAndDyes`。

## ネクタイとダイヤの装飾

- ネクタイ（首/背中）・ダイヤのネックレス（首/背中）・ダイヤのイヤリング（顔）・ダイヤのティアラ（頭）・ダイヤのブローチ（腰。腰の前の左寄りに留める）。
- どれもピクセル単位の箱で組む（斜めはネクタイの剣先だけ）。ネクタイの結び目は剣先より1ピクセル奥。ティアラは5つの山に真珠と桃色の石、ブローチはリボン結びの真ん中にダイヤ、ネックレスは両わきに真珠。ダイヤが光るとき、そばに白い十字の星が出る。ダイヤはピクセルを菱形に並べ、明るい面（`Accessories.gem`）がときどき白くきらりと光る（暗い所でも見える）。染めると金具の色が変わり、ダイヤの色はそのまま。
- 胸（y -7〜-4）と装甲板は胴の前の面より z -2.4 近くまで出るので、胸の上の物（ネクタイの剣先・ネックレスの台とダイヤ・ブローチ）はそれより前に置く（最初は胸に埋もれて見えなかった）。
- イヤリングは髪の殻（x ±4.45）の1ピクセル外、横の髪（z -3〜-1）より後ろに置き、頭の下の縁から下げる（最初は髪に埋もれて見えなかった）。
- レシピ: ネクタイ（糸1・羊毛2）、ネックレス（金塊3・ダイヤ1）、イヤリング（金塊2・ダイヤ2）、ティアラ（金塊5・ダイヤ1）、ブローチ（金塊4・ダイヤ1）。

## 模様の細かさの検査

- 箱は `FxDraw.texBox` で長さに合わせて貼る。32ドットを超える面はない（伸びる所はない）。
- 細かすぎた所: ランタンのガラスと火（絵を1枚まるごと貼っていた）と、斜めの三角（猫耳・ダイヤ・ティアラ・ネクタイの先）。三角も、前後の面は位置から、側面は辺の長さと奥行きから貼るようにした（`FxDraw.prism`）。
- ほうきの穂は前後（z）に長いので、筋が長さの向きに走るよう貼る向きを変えた（`texBox` の zLong）。

## ピクセルにそろえる見直し

- 絵の切り出しの始まりを絵のドット単位にした（`FxDraw.texOffset`）。整数ピクセルの箱なら、辺と絵のドットの境目がそろう。
- 0.18.0 の装飾（魔女の帽子・麦わら帽子・付け毛・モノクル・エプロン・ランタン・ほうき）を、だいたい同じ形のまま整数ピクセル（厚みは 0.5 も使う）の箱に組み直した。

## QIO ダッシュボードをストレージとして使う

- 作業のブロック（作業指令台・資材口・納品口）が隣のストレージを集めるとき（`SupplyPortBlockEntity.collect`）、隣に入れ物がなければ `QioStores.dashboard` を見る。
- Mekanism があるときだけ `compat/mekanism/MekanismQio`（API の `IQIOComponent`・`IQIOFrequency` だけを使う）。`mekanism:qio_dashboard` で、向き（facing。画面の向き）が作業のブロックからダッシュボードへの向きと同じ（裏が接している）、周波数が決まっている（リンク済み）ときだけ。
- 入れ物の見え方: 種類ごとに1枠（数は QIO の量）と、入れるための空き枠1つ。枠の並びは同じ tick の間は変えない。
- 同じ周波数のダッシュボードは、何枚つないでも同じ入れ物を返し、集めるときは1回だけ数える（最初は枚数ぶん重ねて数えていた）。
- Mekanism を入れた回帰 GameTest で在庫の数え方・キャッシュ・アクセス制限を検証。自動化は実効セキュリティが公開のダッシュボードだけを利用する。

## 電力ストレージの充電の枠

- `energy/ItemCharging`: 入れる枠の物（電力を受け取れる物。`Capabilities.EnergyStorage.ITEM`）を装置の電力で充電し、満タンになったら出てくる枠へ移す（出てくる枠がふさがっていれば待つ）。使った電力は装置から減らし、出した電力に数える（出し入れの速さの残りまで）。
- SMESセル・SMESモジュール: 充電の枠2つ（入れる枠は1個まで）を追加。画面は高さ190にしてインベントリを付け、蓄電バーの下に「入れる枠 → 矢印（入れた物の充電の進み）→ 出てくる枠」。ホッパーなど（`ItemHandler.BLOCK`）は入れる枠へ入れ、出てくる枠から取り出す。壊すと枠の物を落とす（`BreakListener`）。
- 核パスタ積層蓄電庫: 既存の物の枠のうち 0 を入れる枠、3 を出てくる枠に使う（紡糸機と同じ枠を、種類で使い分ける）。画面は数値の行の下に充電の枠、ポートのボタンを少し下げた。画面へは装置の種類を送る（以前は紡糸機かどうかだけ）。
- GameTest `smesChargesItemsInItsChargeSlots`。

## RGB染色台のカラーコード入力

- 「染める」の下の入力欄（#RRGGBB。`#` はなくてもよい）。6桁そろったらその色にする（色の輪と明るさも合わせる）。輪やつまみで選ぶと、入力欄も今の色になる。入力中は文字のキーで画面を閉じない（Enter で入力を終える）。

## 装飾の見た目の作り直し

- 模様: `textures/entity/android_decor_grain.png`（汚し）・`android_decor_strands.png`（筋）を、体の1ピクセルに1ドットの細かさで面ごとに切り出して貼る（`FxDraw.texBox`）。
- まぶたは装飾より先に描く（メガネ・モノクルのレンズの奥行きで、まぶたが隠れていた）。
- 妖精の羽はホログラム（背中から浮かぶ、奥へ3枚の半透明の層・光る縁と筋・光の粒）。

## 印刷された食品

- フードプリンター（`food/FoodPrinterBlockEntity`、段階1、作業台の形を決めたレシピ）: タンパク質・炭水化物・甘味それぞれの食材の枠（`FoodPaste.kindOf`、タグ `singulo:food_paste/protein|carb|sweet` の種類だけ入る）から、4 tickに1個、同じ種類のカートリッジへ補う（満腹度の分。食べ物でない小麦・卵は2、ハチミツの巣は3、ほかは1）。補う順は、選んだ（自動なら印刷中・出口の）食品に足りない種類（足りない分の多い順）→ ほかは少ない種類から。入りきらない食材は枠で待つ。容器が残る物（ハチミツ入りの瓶・シチュー）と印刷した食品は食材にしない。
- フードカートリッジ（`food/FoodCartridgeItem`）: ペーストを物の情報 `singulo:food_paste`（種類と量、64まで）に持つ。空ならどの枠にも入り、中身があれば同じ種類の枠にだけ入る。窓の絵（layer1）をペーストの色に染める。
- 宇宙食（`food/PrintedFood`）: 栄養バー（炭水化物4・タンパク質2）、積層ステーキ（タンパク質8）、らせんパスタ（炭水化物6・タンパク質2、採掘速度上昇）、ハニカムケーキ（甘味4・炭水化物3、移動速度上昇）、フルーツゼリーキューブ（甘味4、満腹でも食べられ再生）。印刷の始めにペーストを払い、電力（20 FE/tick）がある間だけ進む。選んだ食品を、ペーストと出口の空きがある間、続けて印刷する。自動（既定）は、出口にある食品 → 並びの順で、ペーストが足りる食品を印刷する。電源を切ると印刷を止める（途中の1個は止まったまま待つ。ペーストにするのは続ける）。
- 見た目: 前にガラスの印刷室、後ろにカートリッジの塔（背面の窓）、上に食材の入口。`FoodPrinterRenderer` が、天井のレールを走る橋・台車・ノズルを動かし、食品の形（層ごとの文字の並び。どの食品も明暗の色を混ぜ、のっぺりさせない）を1ドットずつ折り返しながら積む。出口に食品があれば、できあがった形を台に置いて見せる。背面の窓に、ペーストの量だけ光る柱。
- 動作音（`machine/food_printer_running`、`tools/sounds/recipes.py` の `food_printer`）: 印刷している間（LIT）、`MachineSounds` がくり返し鳴らす。事務のプリンターのように、印刷ヘッドの台車が0.75秒ごとに左右へ「ジーッ」と走り（加速・一定・減速。モーターのうなりは速さにつれて高くなるが音階にしない。ベルトのこすれとレールのゴロゴロ）、折り返しで「カチッ」と止まってペーストを押し出す。4往復ごとに台が1層下がる「ウィッ・カタン」。6秒にちょうど8往復で、継ぎ目でもリズムがずれない（最初の版は音階の高さで鳴らしていて、曲のように聞こえた）。字幕は5言語。
- 画面（`FoodPrinterScreen`、ほかの装置と同じ骨格。幅212）: ヘッダーの右に電源と状態（稼働・待機・ペースト不足・電力不足・出力がいっぱい・停止）、左端に蓄電。上からタンパク質・炭水化物・甘味の行（その種類の食材の枠 → 小さな矢印（ペーストにしている間はその色）→ カートリッジ → 縦長のペーストの目盛りと1個に使う分の印）→ 印刷室の窓（食品の絵を2倍で、下から積み上げる）→ 矢印 → 出口。出口の上の「作るもの」ボタンで、ほかの装置と同じ選ぶ窓（動かせる・×で閉じる。先頭は自動、ペーストが足りる食品は緑の枠）を開く。右クリックで自動に戻す。食品は6つなので、選ぶ窓は1行で行の数は変えない。
- ホッパーなど: 食材とカートリッジを入れ、印刷した食品だけを取り出す。壊すと中身を落とす（カートリッジはペーストを持ったまま）。
- 絵（`tools/food_content.py` の `FOOD_ART`・`CARTRIDGE_ART`）: 1文字1ドットの並びで、輪郭・影・中間・明るい面・つやを描き分ける。輪郭（o・O）の色は決め打ちにせず、となりの色を同じ色相のまま暗くして作る（`outline_colors`）。輪郭が全体を囲んでいない・浮いた輪郭があると生成を止め、`tools/test_food_art.py` でも確かめる。らせんパスタは白い器に盛り、トマトソース・バジル・粉チーズをのせる。カートリッジの絵は 14×14 の内側（10×14）。
- ハンドブックの章「印刷された食品」。GameTest `FoodPrinterGameTests`（4件）。
- GUI の自動撮影（tools/review）には、まだ入れていない。

## ケーブル・パイプのカバー

- カバーの枠（`cable/CoverFrameItem`、段階1、作業台で鉄インゴット4・鉄格子4から8個。四隅の鉄インゴットを鉄格子でつないだ形）。
- 決まりは `cable/ConduitCover`。電線・パイプの全8種類（`CableBlock`・`FluidPipeBlock`）に、状態 `cover`（none・frame・block）を足した。
  - 枠を持って右クリック: 枠を取り付ける（frame）。枠だけのところをブロックで右クリック: そのブロックを1つはめ込む（block）。はめ込むブロックの状態は、その場所にふつうに置いたときと同じ（`getStateForPlacement`。丸太は右クリックした面の軸、くり抜かれたカボチャは顔をこちらへ）で、向きを含めてブロックエンティティが覚えて保存し、クライアントへも送る。ブロック入りの状態にするのは次の tick（`settle`）。先にはめ込んだブロックをクライアントへ届けておかないと、状態だけが先に届いたとき、隣（地面など）の面は隠れるのに枠だけが描かれ、一瞬向こうが透ける。はめ込み中に別のブロックでは上書きせず、外す・壊すときはそのブロックも返す。ブロック入りのカバーにブロックを向けると、ふつうに隣へ置ける（建てるときに邪魔をしない）。替えるときは外してから。
  - はめ込めるのは、ブロックエンティティがなく、すき間のない不透明な1ブロック（向きはあってよい。水に浸かった状態は除く。`allowed`）。ガラス・葉・階段・ハーフ・チェスト・かまど・ケーブル自身は断る（理由を行動バーに出す）。
  - 枠がある間は、選ぶ形が1ブロックいっぱい。当たり判定は、枠だけなら厚さ1ドットの壁の中空の箱（外から当たるのは1ブロックいっぱいと同じで、中へは入れない。いっぱいの箱にすると、描画が内側の面を外の面と同じに隣の明るさで描き、隣が詰まったブロックや地面のとき枠の内側が黒くなる）、ブロック入りなら1ブロックいっぱい。枠だけの間はガラスのように、光を通し（`getLightBlock` 0・`propagatesSkylightDown`）、隣に陰を落とさず（`getShadeBrightness` 1）、窒息・視界をさえぎらない。ブロック入りのときだけ隣の面を隠し、光をさえぎる（`getOcclusionShape`。そのため電線・パイプの `noOcclusion` をやめ、状態で決める。赤石は伝えない）。音と爆発への強さ（`getExplosionResistance`）は、はめ込んだブロックと同じ。
  - つながり・送る量・ネットワークは変わらない（状態を足しただけ）。
  - 壊す: プレイヤーが壊すと、ケーブルは残して、カバーを1つずつ外して落とす（`onDestroyedByPlayer` で `breakCover` が外し、ケーブルは壊さない。ブロック入りのときは、はめ込んだブロックを掘る速さ `getDestroyProgress`。創造モードでは落とさない）。撤去モードのレンチを持っているときは、ふつうにケーブルごと壊す。
  - 外す: 移設レンチ（装置の移設モード）でスニークして右クリックすると、ブロック → 枠の順に1つずつ持ち物へ。撤去モードで外すと、ケーブルと一緒に枠とブロックも持ち物へ（`strip` で先に外し、壊したときに二重に落とさない）。壊すと枠とブロックを落とす。
- 見た目: 枠は、ブロック状態のファイル（多部品）に `cover: frame|block` の部品 `block/cover_frame`（12本の辺に太さ2ドットの鉄の棒）を足す（`tools/cover_content.py` が電線・パイプのモデルを書いたあとに足す）。ブロック入りは `client/CoverModel` が、ケーブルの代わりに、はめ込んだブロックのモデルをその向きのまま描く（描き方の種類・陰・粒子・色付けも、そのブロックのもの）。ブロックがまだ届いていない間は、ケーブルと枠のまま。中の電気の光（`CableRenderer`）と液体（`FluidPipeRenderer`）は、ブロック入りのときは描かない。
- 持ったときの枠は、ブロックと同じ3Dのモデル（アイテムのモデルの親を `block/cover_frame` に）。
- 枠だけを置ける（`cable/CoverFrameBlock`。枠のアイテムはこのブロックのアイテム）。ケーブルを右クリックすると取り付き、ほかの場所では枠のブロックとして置く。置いた枠は光を通し、当たり判定は枠のケーブルと同じ中空の箱。ケーブル・パイプのアイテムで右クリックすると、その場所に置いたとしてつながりを決め、枠付き（frame）のケーブル・パイプになる（ほかのブロックは隣へふつうに置ける。スニークすればケーブルも隣へ）。撤去モードのレンチでブロックの入っていない枠のケーブルを外すと、ケーブルだけが外れ、枠のブロックが残る（`leaveFrame`）。
- ハンドブックの章「ケーブルのカバー」。GameTest `ConduitCoverGameTests`（3件。枠を先に置いてケーブルを入れる、丸太の軸・保存し直し・枠だけの光も確かめる）。

## 取り出せない物を在庫に数えない

- 作業のブロック（作業指令台・資材口・納品口）が隣のストレージを集めるとき（`AdjacentItemStores.androidView`）、入れ物を `ExtractableItems` で包む。取り出しの試し（1個、simulate）が空の欄は空に見せる（数は欄の数のまま）。在庫・取りに行く場所・燃料の場所は、どれも `getStackInSlot` で数えるので、まとめて直る。フードプリンターのカートリッジと食材の枠、装置の入れる欄などを、在庫に数えない。
- 液体（`LiquidStores.at`）は、流体の種類ごとに抜ける量（drain の simulate）だけを数える。化学物質（Mekanism）も、どこかの面から取り出せる量だけを数える。装置の面（`LiquidStores.machine`。まだ残っている素材を数える）は、見えている量のまま。
- 装置の出口の数（`MachineWatch.output`）も、取り出せる欄だけを数える。
- GameTest `foodPrinterAutomationAndBreakingKeepPaste` で、隣の作業指令台の在庫が印刷した食品だけになることを確かめる。
