# 0.11.0 既存機能・寿命管理・性能・翻訳の再レビュー

2026-10-22。対象は `feature/0.11.0` の `ba3457b` と、この報告に対応する修正。新規コンテンツの追加、版番号変更、マージ、公開は行っていない。

## 修正した問題

| 分類 | 問題と根拠 | 修正 |
| --- | --- | --- |
| P2・ワールド参照 | スタビライザー、シールド、リアクター、ワームホールの静的レジストリは、外側が `WeakHashMap<Level, …>` でも、値の集合が装置を強参照し、その装置がLevelを参照する。終了時の除去に依存する参照循環になっていた。 | 集合の装置参照も弱参照にし、サーバーのLevel終了イベントで該当Levelの登録を明示的に除去する。通常のチャンク解除で既に行う `setRemoved` の処理は維持する。 |
| P2・演出と戦闘ログ | 形成演出キューがServerLevelを保持し、閉じたLevelの時刻が進まないと残りうる。戦闘ログの叩きつけ記録も、実際の落下ダメージが来なければ期限切れ後もボスを強参照した。 | Level終了でキューと帰属記録を解放。戦闘ログは落下ダメージの有無に依存せず期限切れ・除去済みボスを取り除く。時間場、アリーナの保護、アンカーの実行時の枠もLevel終了で片付ける。保存済みの進行やチケットデータは消さない。 |
| P2・重力ツール | UUIDごとの左クリック、チャージ、投射直後の対象ID、浮遊対象がログアウト等で消えず、再接続や別ディメンションへ持ち越される。 | ログアウト、ディメンション変更、リスポーンで操作状態を解放し、サーバー終了でも初期化する。 |
| P2・クライアント | ShapeCacheは最後のLevelを強参照し、訪問した位置が無制限に増えた。別ディメンションへの切替でも音・スキャナー・投影が古い状態を持ち越しうる。 | Level参照を弱参照にし、形状キャッシュは4,096件のLRUに制限。種類が違うコントローラへ入れ替えた位置でも再判定する。Level終了時に形・投影・スキャン・再生中の音を片付ける。解読済み記録はディメンション移動では維持し、サーバー切断時に消す。 |
| P2・描画履歴 | 圧縮炉・熱炉の打撃履歴とリアクターの点火履歴が位置だけを鍵とし、訪問済み位置が残り続け、別のワールド・別の装置とも衝突した。 | 実際の装置を弱い鍵として追跡する。描画計算・モデル・テクスチャ・演出の周期は維持する。 |
| P2・大出力 | 共通発電バッファの `energy + amount` がintで桁あふれする。出力設定や発電倍率を大きくしたとき、上限で止める前に蓄電が負になりうる。 | 加算をlongで行い、従来の容量に収めてintへ戻す。通常の発電量、容量、変更通知の条件は維持する。 |

大出力は共通ストレージ単体でも再現した。容量200,000,000、蓄電199,000,000に `Integer.MAX_VALUE` を発電させると、修正前は **-1,948,483,649** になった。回帰テストでは蓄電100,000,000からの加算、満杯時の再加算、通常の消費・発電と通知回数を確認する。これは通常設定の出力を引き上げる変更ではない。

## 機能・見た目を維持する性能改善

機械のレシピ照合、質量モード、GUIのレシピ一覧で行っていた、全機械レシピの走査・調整・並べ替えを共有の不変インデックスへ変更した。レシピ一覧と設定リビジョンが変わったときだけ再構築する。装置の材料や電力が変わるたびに同じ一覧を作り直さない。

- 優先度、材料数、IDの順序、調整後の値を従来の計算と全機種で比較するGameTestを追加。
- `/reload` による削除・復元、設定変更、選択番号の同期を検証。全機械が新しいレシピ一覧を検知し、待機中でも再照合する。
- キャッシュはRecipeManagerを弱い鍵とし、値からLevelやマネージャーを参照しない。終了時にも破棄する。
- 再生中のブラックホールの環境音について、既に音がある場合に毎tick不要なSourceラッパーを生成しないようにした。

同じGameTestプロセス内で精密組立台の一覧を1万回取得した記録は、初回は新方式 **1.67 ms**、従来相当の走査・調整・ソート **796 ms**、最終再検証ではそれぞれ **2.74 ms / 823 ms**。計測値をテストの合否条件にはしない。これは温まった一覧取得の比較であり、TPS・FPSや全体の何倍高速化を示す値ではない。レシピ変更時の再構築には従来同様の処理が必要になる。

レシピJSON、材料コスト、装置の出力、モデル、テクスチャ、構造物テンプレートは変更していない。

## 翻訳と説明の修正

5言語各2,815キーについて、キーと書式引数をチェックした。日本語と英語の引数比較も検証へ追加した。意味の確認では、機械・電力・入出力・道具・進行案内を実装およびレシピと照合した。

| 対象 | 修正 |
| --- | --- |
| 序盤ガイドの冷却塔 | 5言語に残っていた「約240 FE/t」を、既定設定・高さ7の **約1,786 FE/t** に訂正。供給が足りなくても進捗を保って待つことを説明する。1250 FE/t × 20tick / 100mB、速度7/5、丸め後14tickから、実際の1回は25,004 FE / 100mBになる。 |
| 段階2の電力不足 | 「停止せず遅くなる」と読める説明を、進捗を保って給電を待つため平均生産速度が下がるという説明へ統一。 |
| 設定カード | 面・自動搬出、同種の機械間のレシピ選択、Pリアクターのスピン目標・投入間隔という実装上の対象を5言語で説明。保存内容の表示も面設定だけという旧表現から更新。 |
| シールド塔の導波管 | 日本語にあった「尖塔の中ほど」の設置位置が英語と追加3言語から抜けていたため補完。 |
| 中国語 | 自動搬出の「自动弹出」「自动排出」を「自动排出」に統一。 |
| 韓国語 | シールド塔、冷却原子トラップ、制御ユニットについて、ガイドとアイテム表示の呼び名を統一。案内文の助詞も修正。 |

`tools/check_gameplay_text.py` は実レシピと最小の塔の高さから消費を計算し、5言語の序盤ガイドを照合する。翻訳の用語チェックとともにPRの検証へ追加した。これは全文章の意味や自然さを自動で保証する検査ではない。

## 検証と限界

- 既存機能を含むGameTestは、修正途中で481件が成功。大出力の回帰1件を追加した最終の **482件がすべて成功**。通常のJava 21ビルドと配布JAR検査も成功し、GUI検査用コードの混入なし。
- 実クライアントでキャッシュ上限・クリア、スキャン・投影のクリア、ディメンション移動での記録維持を確認。
- 同じクライアントLevelを開いたまま、描画履歴に登録した3個の検査用装置がGCで回収されることを確認。ゲームへ配布するクラスに検査ハーネスや `System.gc()` は含めない。
- 既存の14枚の実クライアント描画撮影も完了。モデル、実績ツリー、支援者名簿、翻訳・実装数値の検査と、公開検証ツールの9件のユニットテストも成功。
- 実際のMekanism本体を入れた化学物質連携のGameTestが1件成功。

再実行には `tools/review/prepare_v011.py` の後、`./gradlew -I tools/review/runtime.gradle runClient` を使う。`build/v011-review/screenshots/runtime-check.txt` と `SINGULO_RUNTIME_CACHE_COMPLETE collected=3` が寿命検査の完了条件。描画撮影は従来と同じ14枚。

静的な参照経路の確認と、特定の参照解放・GCの試験を行った結果である。何日も稼働させたヒープ推移、多人数での大規模工場、すべての外部MODとの組合せは測っていない。翻訳も母語話者による全文章の校閲を終えたという意味ではない。

今後の性能調査候補は、大量の重力パネルの経路探索と、非常に多くの端点を持つ送電網の経路キャッシュである。今回、根拠なく上限や処理間隔を変えて配電・演出の挙動を変える最適化は行っていない。
