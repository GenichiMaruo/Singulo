## 確認した問題と修正

| 優先度 | 問題 | 対応 |
| --- | --- | --- |
| P1 | 稼働状態で保存された重力・日照パネルを新しい受電器が認識すると、電力なしでも稼働状態が残る | 再探索時に保存された実ブロック状態と一時的な管理状態を照合し、不足時に停止させる。修正前に両方の回帰試験が失敗することを確認。 |
| P1 | 受電器のチャンクのアンロード後も、読み込み中の接続パネル・無重力領域が残る | アンロード時に担当パネルを停止して他の受電器へ再探索を依頼する。無重力領域もチャンク・Level終了時に索引から除く。修正前のアンロードコールバック試験で再現。 |
| P1 | 薄い無重力領域へ高速で落下し、同じtickで着地するとダメージが発生する | 着地時の落下イベントでも稼働中の無重力領域を判定し、ダメージを無効化する。修正前に実際の移動・衝突で再現し、領域外では通常どおりダメージを受ける比較ケースも追加。 |
| P2 | 衝撃発電パネルが高さの大きい無重力区画でも通常パネルの単価で電力を予約する | 担当枚数ではなく、実際に支払った種類別・高さ別の消費電力から100tick分を予約する。乗算もlongの範囲で飽和させる。 |
| 性能 | 通常tickでも全パネルの担当枚数とBitSetの有効数を数え直す | 担当枚数を探索時に集計し、全パネルが稼働中の通常tickは受電器数に比例する処理にする。構造の再探索や電力不足時は従来どおりパネルごとに照合する。 |
| 検証基盤 | 配布検証が490件を要求し、既存の追加後495件と一致しない | 回帰6件を既定のGameTest対象に加え、必須501件として厳密に検証する。 |
| 検証基盤 | GUI検査の面設定・レシピ選択フラグを併用すると片方の検査しか走らない。また古い撮影画像が残る | 両方を指定した場合は通常の機械・面設定・レシピ選択を順番に実行する。準備時に前回の画像と集計ファイルを削除し、新しい証跡だけを検査する。 |
| 表記 | 新しい設計図が入手先・建材一覧を通常の説明文に長く表示する | 全5言語で短い図面の説明に整理。日照パネル2種と無重力ブロックにも短い通常表示を追加し、操作・条件はShift詳細に残す。 |

併せて、コントロールボックスの高さがint上限で1へ折り返す加算、保存電力が負になる読み込み、アンロード済み隣接チャンクへの参照を防いだ。

## バランス

| 構成 | 通常の消費電力 |
| --- | ---: |
| 日照パネル25枚（5×5） | 500 FE/t |
| 日照パネル81枚（9×9） | 1,620 FE/t |
| 日照パネル256枚（16×16） | 5,120 FE/t |
| 無重力25枚・高さ5 | 750 FE/t |
| 無重力25枚・高さ8 | 3,075 FE/t |
| 無重力25枚・高さ10 | 7,875 FE/t |

無重力の単価は `round(30 × 1.6^(高さ−5))` FE/t。1枚あたり高さ8で123、10で315になる。標準のミュオン触媒核融合炉4,000 FE/tを基準にすると、小さな区画は運用しやすく、広い・高い区画は追加の発電を必要とする。1枚あたりの丸め後の値を枚数分支払う。

設計図は再利用できるが建材の材料は消費する。追加された設計図は建築・設備の選択肢を広げ、既存の主進行に新たな必須の抽選品を挟むものではない。現時点でこれらの消費電力や材料費を変更する必要は認めなかった。受電器の受電上限を広げても、給電元とケーブル経路の容量制限は残る。
