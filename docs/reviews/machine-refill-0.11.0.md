# 0.11.0: 素材の補充後に加工が再開しない問題

## 再現と原因

圧縮機へ木炭4個を入れると、3個を消費して炭素粉2個ができ、木炭1個が残る。完成品を取り出し、材料不足で待機した後、その木炭へShiftクリックで2個を補充すると、入力は3個あるのに加工が再開しない。修正前の実コードとGameTestで再現した。通常クリックで補充する操作は比較用のテストとして成功した。

`AbstractContainerMenu.moveItemStackTo` は既存スタックの個数を直接変更し、`Slot.setChanged()` を呼ぶ。NeoForgeの `SlotItemHandler` はその通知を空のダミーコンテナに送るため、本物のインベントリの `onContentsChanged` が呼ばれない。その結果、装置のレシピ再判定フラグが更新されず、補充前の「作れるレシピなし」が残っていた。

入力を空にしてから置き直す操作や、アイテムハンドラーへの自動搬入は、別の変更通知経路を通る。このため、同じ量でも操作によって発生の有無が変わる。

## 修正

- `NotifyingItemSlot` を追加。スロットの変更通知を実際の変更可能なアイテムハンドラーへ届ける。
- 加工装置の入力・出力・触媒・アップグレード枠に適用。既存スタックへ補充する操作もレシピを再判定する。
- 発電機、触媒装置、共通小型装置、Pリアクター、ワームホール固定化装置の画面にも適用し、同じ通知漏れを防止。
- レシピ、材料数、電力、加工速度、スロット配置は変更しない。

## 検証

- 修正前: 圧縮機のShift補充テストが失敗し、停止を再現。
- 修正後: 圧縮機の通常クリック／Shift補充、焼成炉と触媒反応器の残り素材へのShift補充を、実際の加工完了まで確認。
- 発電機・触媒装置・小型装置・Pリアクター・ワームホール固定化装置のメニューで、Shift補充時にアイテムハンドラーへ変更通知が届くことを確認。
- 既存テストを含む必須GameTest **440件**とJava 21のビルドを検証。

対象は `feature/0.11.0`。バージョン番号は変更しない。
