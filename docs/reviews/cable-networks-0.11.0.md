# 0.11.0: 電源の優先順位・区間ネットワーク・切断時の表示

## 給電の規則

受電装置ごとに、接続したケーブルをたどった距離が近い電源から供給する。同距離は電源の座標と接続面の固定順で決める。近い電源の蓄電量・取り出し上限・その経路のケーブル容量で不足する分を、次の電源が補う。

遠い電源のtickが先に実行されても、その受電装置へ近い電源から取り出せる分を先に供給する。呼び出した電源が支払うのは、その電源から実際に送った分だけ。他の電源から取り出した分を二重に請求しない。受電側の上限と同tickの受電済み量も管理する。受電先が複数ある場合は、その供給要求の入口から近い順に処理する。

例えば受電の空きが6,000 FE、近い電源の残量が4,000 FEの場合、近い電源が4,000 FE、遠い電源が2,000 FEを支払う。近い電源が空なら遠い電源が6,000 FEを補う。近い経路の銅導線で2,000 FEに制限され、そのうち2 FEが失われる例では、遠い超伝導経路が4,002 FEを補い、装置へ6,000 FEが届く。

近い電源を先に取り出す処理は、外部取り出しに対応するFE/LongEnergyStorageの電源に適用する。Singuloの発電機・SMES・リアクター・クリエイティブ電源が対象。押し出すことしかできない他modの電源は、押し出した要求を受けた時点で配分に加える。まだ届いていない電力を予測して確保したり、電源の中身を直接変更したりしない。

シミュレーションはネットワークの会計状態だけを複製し、電源・受電装置・実送電の枠を変更しない。

## 長いケーブルの処理

ケーブルごとのサーバーtickを廃止し、ネットワークが以下をまとめて保持する。

- 接続点: 分岐、端、装置の接続位置。
- 区間: 接続点の間にある、途中で分岐しない連続したケーブル。
- 区間の最小容量、損失合計、本数。
- 接続点間の最短経路と、受電装置ごとの電源の優先順位。
- 接続点・区間・装置の同tickの送電済み量。

送電のたびに直線の全ケーブルをたどらず、通る区間と接続点の容量を確認する。経路探索は圧縮したグラフに対して行い、結果をキャッシュする。稼働表示の切替だけでは再探索しない。形成前に置いた搬入出ポートも候補として保持し、形成後の能力を参照できる。

256本の直線を使ったGameTestでは、接続点2個・区間1個・使用量の制約3個で処理し、100回の送電で経路キャッシュ1個を使い回す。各ケーブルのティッカーがnullであることも検証する。ネットワーク途中へ直接FEを注入する特殊な呼び出しは、その位置で区間を分割し、既に使った容量を引き継ぐ。入口を変えても同tickの上限を回避できない。

配線の設置・撤去・読み込み状態の変化では接続を調べ直す。無効になったネットワークはケーブルへの参照を外し、停止中の配線が未読込チャンクのブロックエンティティを保持し続けないようにする。ネットワーク内部には電力を貯めないため、分割やチャンクの解除で電力を失わない。

## 負荷の範囲

初回と配線変更後の構築は、読み込まれたケーブル本数に比例する探索を行う。通常の送電は、接続装置数と通過する区間・接続点数に応じた処理になる。長い直線を伸ばすだけでは、その区間の電力会計の処理数は増えない。分岐や装置を増やせば処理量は増える。

描画には個々のケーブルの状態が必要なので、通電中の区間を通常10tickごとに展開し、表示が変わったブロックだけを更新する。停止したネットワークは表示を消した後、定期更新対象から外れる。切断時の消灯は例外として即時更新する。

これは処理構造とGameTestによる確認であり、大規模な実ワールド間のTPS比較を測定した結果ではない。

## 切断時の光る線

サーバーでは、配線を無効にしたその場で旧ネットワークの発光を消す。10tickの表示更新周期を待たない。取り外したケーブルのCapabilityを他modが保持していても、以後の受電は0を返す。

クライアントはブロックエンティティの削除通知も扱い、ローカルでブロックが消えた時点で接続していた表示を隠す。サーバー応答を待つ必要がない。表示の元データは保持し、採掘が取り消されてブロックが戻った場合は元の発光へ戻す。

ネットワークごとの表示世代を同期し、切断前の遅れて届いた点灯データでは再点灯しない。再構築後の正しい世代の表示は反映する。クライアントの単なるチャンク解除では、ケーブルごとに全体を探索し直さない。

実際のMinecraftクライアントで、予測削除、切断前の表示データの再受信、削除の取り消し、確定した切断を検証した。

[通電中](cable-networks-0.11.0/powered.png) / [切断直後](cable-networks-0.11.0/cut.png)

描画確認の再実行（開発用の一時ワールドを作成する）:

```sh
python tools/review/prepare_gui.py
./gradlew -I tools/review/cable.gradle runClient
```

画像と結果は `build/gui-review/cable-screenshots` に出力する。検証用のソースは通常のビルドに含まれない。

## テスト

ケーブル専用の名前空間 `singulo_cable` を用意し、短時間で個別検証できる。実行例:

```sh
./gradlew runGameTestServer -PtestNamespace=singulo_cable -PtestTickRate=200
```

既存6件に加え、近い電源を先に使う呼び出し順2通り、容量不足と損失の補完、同距離の順序、空の電源、切断時の消灯・受電停止、装置の発光変更でのキャッシュ保持、ローカル消灯、途中への給電と容量の引継ぎ、256本の直線の計10件を追加した。

最終検証: 通常ビルドと必須GameTest **462件すべて成功**。ケーブル専用は既存6件＋追加10件の16件。実クライアントの再現ハーネスでは、通常のクリエイティブ採掘操作で即時消灯し、採掘取り消しでは発光が戻ることを確認した。切断前の表示タグを再受信しても消灯を維持した。5言語・モデル・実績・支援者名簿と公開検証ツールの9件も確認済み。通常ビルドに描画ハーネスを含めない。
