# 0.11.0: 使用済み部品のアイテム搬出

## 問題と変更

加工装置で制御ユニットなどの最後の1回を使っても、劣化品や使用済み原本が入力枠に残り、出力専用のアイテム搬出処理から回収できなかった。

最後の使用で生じた残り物を搬出待ちとして記録し、通常の完成品を配置した後、出力枠に空きがあれば移す。出力枠が完成品で埋まっている場合は、元の入力枠で保持する。その枠もアイテムハンドラーの取り出し対象になり、ホッパー、アイテムパイプ、マルチブロック搬入出ポートから回収できる。空きができた場合の出力枠への移動は、装置の電源がオフでも行う。

隣接インベントリへ押し出す処理は、既存の自動搬出スイッチと面設定に従う。新しい装置の自動搬出は引き続き初期オフ。ホッパーやパイプによる引き出しは、搬出可能な面であればスイッチがオフでも使える。

## 保持する状態と境界

- 残り物のアイテムスタックをそのまま移し、使用回数と修復履歴を維持する。
- 搬出待ち品は再び材料として照合せず、同じ入力枠への追加搬入も受け付けない。
- 搬出先が満杯の場合は保持し、アイテムを消去・ドロップしない。
- 搬出待ちの記録を保存し、再読込や移設レンチの保存経路でも引き継ぐ。スロット配置が変わった保存データの番号も既存の変換規則に従う。
- 入力枠から回収・交換した時点で搬出待ちを解除し、次に入れた未使用品を搬出しない。
- 修復のために外から投入した原本や劣化品は通常の入力として扱う。使用済みかどうかだけで自動搬出を決めない。
- 使い切ると消滅する残響の欠片などは、従来どおり残り物を作らない。無限触媒は搬出待ちにならない。
- 対象は共通の加工装置。専用の触媒装置の触媒枠は従来から外部アイテムハンドラーで回収でき、今回はその入出力仕様を変えない。
- 更新前から入力枠に残っている品と、修復用に投入した品は区別できないため、旧データから搬出待ちを推測しない。今回の処理で最後の使用を迎えた品から記録する。

## 検証

6件のGameTestを追加。

1. 使用中の原本を搬出せず、使い切った原本だけをパイプ相当のCapabilityから回収。シミュレーション、二重取り出し、交換後の新品も確認。
2. 出力枠を完成品が占有した状態で保存・再読込し、完成品回収後に使用済み原本が出力枠へ移ることを確認。
3. 実際のホッパーが自動搬出オフの装置から完成品と使用済み原本を各1個回収。
4. 自動搬出オフでは保持し、オンにすると隣のチェストに完成品と使用済み原本を各1個搬出。
5. 形成した極低温冷却塔で、修復済み制御ユニットの最後の使用から劣化品を生成。搬入出ポートで取り出し、修復履歴が2回になっていることを確認。
6. 修復用に投入した使用済み原本は搬出せず、実際に修復して使用回数12・修復履歴1の原本が出力されることを確認。

初回検証では、ホッパーをブロック状態だけで停止したテストと、絶対座標を再変換したポートのテストが失敗した。前者はレッドストーンで停止する方式に、後者は正しい絶対座標に修正した。

最終確認はビルドと必須GameTest **446件すべて成功**。配布JARとJava 21互換性、言語カタログ、モデル、実績、支援者名簿、公開検証ツールの9件のテスト、差分の空白チェックも成功した。
