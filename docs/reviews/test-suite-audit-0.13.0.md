# 0.13.0 テスト全体の調査と改善

評価日: 2026-10-29（日本時間）。対象: Minecraft 1.21.1 / NeoForge、`feature/0.13.0`。

## 取り込みと対象範囲

Claudeによる10コミットを`7b0d13b3`までfast-forwardで取り込んだ。その状態では通常のGameTest 559件が成功した。既存53クラス、CIの3ジョブ、GUI・描画連携の開発用ハーネス、翻訳・モデル・実績・公開用検証スクリプトを棚卸しした。

今回の追加は6件。最終的な通常GameTestは565件、実Mekanism専用は1件で、合計56クラス566メソッド。検証ツール自身の単体テストは30件になった。

## 見つかった問題と修正

| 問題 | 対応・検証 |
| --- | --- |
| 異なるクラスに同じGameTest名があり、個別指定・結果照合が曖昧だった | 名前を一意に変更。ソース全体の重複を検出する検査を追加 |
| 完了件数だけでは、同件数の別テスト・一部未実行・重複結果を検知できない | ソースの一覧、実際の登録、各成功結果を照合するJSON証跡を追加。不足・重複・任意扱い・途中終了を拒否 |
| テストクラスと補助コードが製品JARへ入っていた | Gradleの`gameTest`ソースセットに分離。内部クラスも含めた混入拒否を実ZIPによる単体テストで確認 |
| 偽プレイヤーの`discard()`だけではサーバーの参加者一覧に残る | 成功・失敗・タイムアウト時に後始末する`TestScope`を追加。ログイン済みプレイヤーも共通管理。失敗経路の回帰検査を追加 |
| テンプレート外に移動させる飛行検査が、チャンクの実稼働開始と競合していた | 飛行範囲をテンプレート内へ移動。実エンティティ120 tick、降下、高空からの射撃禁止という条件を維持。時間切れは600から240 tickへ短縮 |
| 完了リスナーで強制読み込みを解除すると、次のバッチが取得したチケットを解除する可能性がある | バッチのチケット解除は標準ランナーに任せる。完了時の後始末から共有チケットの解除を除外 |
| チャンク待ちのままでは標準のテスト時間切れが開始せず、停止が長引く | 120秒間、どのテストも完了しない場合の監視を追加。失敗を成功へ読み替える処理や再試行は追加していない |
| 非同期の設定変更テストが途中失敗すると設定が残る | 完了スコープによる設定復元を追加。冷却塔ヘルパーの不要な可変static状態も除去 |
| 施設生成の重複検査が、小部屋が複数あるだけで主要な部屋の重複も許していた | 主要な部屋の一意性を直接確認する条件へ修正。120 seedの配置検査を維持。描画用乱数を固定 |
| 資材口の不正な負数ボタンが通常の操作として処理される | 回帰検査で修正前の失敗を再現し、ボタン・シフト移動スロットの上下限を検査するよう修正 |
| 資材口の見本登録・触媒の出力待ち保存について検査が不足していた | 見本登録で現物が増減しないこと、重複登録、取り外し時の設定初期化、装填中寿命・予備・排出待ちの保存復元と一度だけの排出を追加検査 |
| GUIのサイズ変更直後、黒い画像を撮影する場合があった | 実際の描画2フレームの完了を待つ方式へ変更。画面が取り替わっていないことと、全205画像の存在・寸法・黒画面でないことを確認 |
| 新しい資材口のGUIが画面一覧に含まれていなかった | 空欄・8件登録・実ツールチップを5言語で追加。計15画面と350個のインベントリ中心の画素検査を追加 |

修正前の資材口検査は不正ボタンの受理を検出して失敗し、修正後は関連37件が成功した。触媒の出力待ちについては、出力が満杯でも保留が残り、保存復元して空きを作った後に失活触媒がちょうど1個出ることを確認した。

## 時間の短縮

同じワークスペースでの比較値。サーバーのテスト完了表示または個別結果の時間を使用し、Gradle起動・依存取得などとは分けた。実プレイのTPSや、別のCIマシンでの所要時間を保証する数値ではない。

| 対象 | 改善前 | 改善後 | 検証内容 |
| --- | ---: | ---: | --- |
| 通常GameTest全体 | 559件 約174秒 | 565件 約100.5秒 | 全件の一致と成功を照合。件数を6件増やして約42%短縮 |
| 育成の純度・寿命検査 | 約39.3秒 | 関連検査で約0.44秒 | 既定の約14,400回の実装処理を直接実行。既定の育成回数と寿命の条件を確認 |
| 機械GUI 205画面の撮影 | 約123秒 | 約35秒 | 固定tick待機から実描画完了待ちへ変更。画素検査も成功 |
| PNG 1枚の読み取り | 約3.24秒 | 約0.16秒 | Pythonの逐次復元からPillowへ変更。比較画像の全RGB値が一致 |
| 検証ツール28件の実行 | 約9.4秒 | 約0.6秒 | 不変なソース一覧の反復読込を抑制。その後2件を追加し、計30件も約0.7秒で成功 |

育成検査では、ワールド全体と他の装置を14,400回動かす必要がなかった。実際の装置の`serverTick`を呼び出して電力履歴と寿命の積算を確認する形へ変更した。別の育成槽テストでは、通常のワールドtickによる稼働、電力不足、レシピ・設定の連携を引き続き検査している。

レシピ一覧の再利用・在庫接続キャッシュ・密な依存関係の検査では、結果一致、再利用、無効化、同tickの状態変化という回帰条件を残し、大量の時間比較ループだけを`-PtestBenchmarks=true`で実行するようにした。

## 維持した検査と実行方式

- 素材の種類違い・バックパックの有無で経路が異なる作成検査は、それぞれ残した。4096個の作成・正確な納品、満杯時の停止、地面へのあふれ防止も維持した。
- 施設の120 seed、実ワールドの装置・ケーブル・範囲効果・保存復元、レシピ置換と設定変更の検査を維持した。
- 実Mekanismの専用実行と、Sodium・Distant Horizonsの実クライアント実行を分離したまま維持した。
- CIの3ジョブは引き続き並列。描画ジョブの9件は専用ワールドの作成と独立した検証を兼ねるため、通常ジョブとの重複を残している。
- 製品JARの重複した検査を公開前ゲートへ集約し、ゲート自身について、欠けた結果・途中終了・重複完了ログ・新しいJava・テストコード混入を拒否する単体テストを追加した。
- 修正中は`-PtestClasses=...`で必要なクラスだけをコンパイル・登録できる。存在しないクラスは事前に拒否し、部分実行の証跡は公開用ゲートを通さない。
