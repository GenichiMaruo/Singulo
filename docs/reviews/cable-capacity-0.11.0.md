# 0.11.0: ケーブル経路ごとの送電容量

続く電源優先・区間処理・表示修正は [追補](cable-networks-0.11.0.md) を参照。

## 原因

`EnergyNetwork.build` が接続されたすべてのケーブルの容量の最小値を計算し、網全体の1 tickあたりの送電上限としていた。銅導線が行き止まりの枝に1本あるだけでも、別経路の超伝導ケーブルは2,000 FE/tに制限された。

極低温冷却塔の既定の受電上限は1回10,000 FE。超伝導ケーブル自体には1,000,000 FE/tの容量があるが、従来の網全体の制限により本来の受電能力を使えなかった。

## 修正

ケーブルごとの容量を記録し、受け手へ送る直前に、その受け手までの経路で残っている容量の最小値を調べる。別の分岐や行き止まりの容量は計算に入れない。

接続点・区間の1 tickごとの使用量を管理するため、複数の入口、複数の受け手、同じtick内の繰り返し送電が同じケーブルを共有しても定格を超えない。共有しないケーブルの使用量は互いに制限しない。

シミュレーションでは呼び出し内だけの仮予約を使い、複数の受け手への見込み量を合計しても共有部分の容量を超えない。実際の蓄電量や次の呼び出しの送電枠は変更しない。実送電済みの容量はシミュレーションでも考慮する。

ケーブルのFE Capabilityが返す容量も、その口にあるケーブルの容量へ変更した。上限なしのケーブルで送る場合に丸め計算がlongの加算でオーバーフローしないよう、配分量の切り上げ式も変更した。

経路選択は従来どおり、入口からケーブル本数が最少となる経路を使う。今回は複数経路への分割や最大流量を探す機能は追加していない。装置自身の受電制限、ケーブルの定格・損失係数は変更していない。

## 検証

6件のGameTestを追加。

1. 超伝導ケーブルの行き止まりに銅導線を接続しても、100,000 FEを損失なしで送れる。口の容量表示とシミュレーションも確認。
2. 通電する銅導線の枝は2,000 FE/t以下に収まり、超伝導側の受け手には50,000 FEを送れる。受電量の合計が送電側の支払量を超えない。
3. 2つの入口が同じ銅導線を共有すると、同一tickの合計が2,000 FEを超えず、次のtickに枠が戻る。
4. 複数の受け手へ分配するシミュレーションでも、共有する銅導線の容量を重複計上しない。
5. 同じ網につながっていても、ケーブルを共有しない別入口の送電は独立した容量を使える。
6. 形成した極低温冷却塔の搬入出ポートに超伝導ケーブルで接続し、別枝の銅導線があっても装置本来の上限10,000 FEを受電できる。

既存の直列銅導線による制限、通電経路の描画、上位ケーブルと大容量送電のGameTestも合わせて検証する。

全件検証で既存の形成演出テストに、別のテストの粒子キューを全体件数で比較する依存が見つかった。送電の6件とは別の失敗で、形成自体は成功していた。このテストを専用バッチへ分離し、前の演出が終了してから建造するよう修正した。ゲーム本体の形成処理は変更していない。

最終の必須GameTest **452件すべて成功**。追加6件、直列の銅導線による制限、既存の大容量送電、形成演出テストを含む。5言語カタログ・モデル・実績・支援者名簿、公開検証ツールの9件のテスト、差分の空白チェックも成功した。
