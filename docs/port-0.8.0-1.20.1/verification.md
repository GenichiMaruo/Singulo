# Singulo 0.8.0 / Minecraft 1.20.1

基準: Minecraft 1.21.1版の公開ソース `8575bced07f2b16bec9e46f8bb33bd85b224cddb`。既存の `port/1.20.1-forge`（47.4.26）と `port/1.20.1-neoforge`（47.1.106）へ移植する。mainは1.21.1専用のまま維持する。

## 1.21.1版の公開記録

[CurseForge file 9203114](https://www.curseforge.com/minecraft/mc-mods/singulo/files/9203114) をMinecraft 1.21.1 / NeoForge / Betaとして公開済み。
[公開ジョブ](https://github.com/GenichiMaruo/Singulo/actions/runs/38842131306)では全348件のGameTestが成功した。送信した成果物とCurseForge CDNから取得したJARのSHA-256が一致する:

`16a935347252ac1c9724ff7789061ed1e9dbea941ae4af5dac49b4d640574ea3`

## 移植内容

- 並行作業・装置待ち・燃料と面の自動判定、範囲カード・測量メガネ・経路、巡回・警報・記録、暮らしの仕草を移植。
- 地下研究所・動力復旧・ファウンドリ・再戦、アルマとノクス、ビットの追従・斬撃・帰還を移植。
- 実績73件とオフライン完了通知を移植。既存IDと条件名を維持する。
- Java 17、1.20.1のブロック操作・描画・SavedData・プレイヤー永続NBT・Forge系APIを使用する。構造物はDataVersion 3465、データの配置は1.20.1の複数形、pack formatは15。
- 範囲カードはNBTの記録状態に応じてスタック上限を64／1へ変える。化学物質見本もNBTで種類・量を保存する。
- 1.20.1のBlockPosはCompoundTagなので、巡回路とファウンドリの装置位置の読み込み型も合わせる。レベル未接続時のブロック状態読み込みには静的レジストリを使う。
- 試作機メモリの受領履歴は既存のPlayerDataへ保存し、死亡時にも引き継ぐ。
- Mekanism 10.4.16.80ではガス・注入材・顔料・スラリーが別レジストリ／能力になっているため、4系統を扱う専用アダプターを実装。ガス以外は種類の接頭辞を付け、同名の別系統を混同しない。
- 基本ケミカルタンクのアイテムには1回1,000 mBの転送制限がある。上限を迂回せず、部分的な出し入れの総量とSIMULATEの非破壊性を検査する。

## バランスの一致

1.21.1版の全249レシピを、1.20.1のJSON形式・共通タグ・Forge条件に正規化して比較し、一致を確認した。材料・数量・出力・時間・消費電力・要求ティアに移植独自の変更を加えない。

[照合用マニフェスト](recipe-parity.json) は公開済み1.21.1ソースの正規化結果をハッシュ化したもの。`python3 tools/check_recipe_parity.py` で各ブランチの全レシピを照合する。

## 検証の進め方

既存1.20.1のチャンク準備・片付け・作業場の余白などの修正を維持する。通常の必須試験は次の6群、合計360件（元の348件＋旧版固有10件＋0.8.0の保存形式2件）。Mekanismは別に2件の専用試験で確認する。

| 名前空間 | 必須件数 | 内容 |
| --- | --- | --- |
| singulo | 252 | 既存装置・探索・旧版互換 |
| singulo_automation | 49 | 作業・巡回・暮らし |
| singulo_reactor | 21 | 炉 |
| singulo_prototype | 10 | アルマ・ノクス・ビット |
| singulo_progression | 13 | 実績・回帰・旧版NBT保存 |
| singulo_lab | 15 | 研究所・ファウンドリ |
| singulo_mekanism | 2（任意構成） | 実タンク・4系統の化学物質 |

各群を新規ワールドで独立実行し、Gradleで成功報告の有無と件数を確認する。CIは通常6群と実Mekanism構成を分け、GUIは通常の群で20画面を実クライアントから撮影し、PNGの在庫表示を検査する。GUI・戦闘の開発用ハーネスは通常のJARへ含めない。

現時点でForgeの試作機＋実績21件と研究所15件、NeoForgeの保存形式を含む実績13件、Forgeの化学物質基本テスト1件が成功している。追加の全体・GUI・4系統検証を継続し、最終コミットのCI結果とマージ判断は各PRのレビューへ記録する。未完の検証を成功として扱わない。

全ティア通しプレイ・大規模負荷試験・他modの全装置構成は未網羅。1.20.1の過去の毛刈り・応戦後復帰の試験差異は、今回の検証で根拠を確認するまで解消済みとは扱わない。

追加試験の配置確認では、旧版用に4ブロックずらした既存の作業場と、新しい試験の位置が一致せず、チェストがステーションを上書きすることを検出した。追加された位置と経路判定の原点を同じ余白へそろえ、納品数・時間上限・製品の動作は変更せず再検証する。

初回CIでは両ローダーとも自動化49件・炉21件・試作機10件・実績13件・研究所15件・Mekanism 2件が成功した。一般群では次の試験配置の問題を検出したため修正し、再実行する。

- スキャナー: 遠方へ移した試験位置にも自然生成鉱石があり、感度不足の件数へ加算された。半径24の走査球を空にしてから既知の鉱石を配置し、正確な件数の判定を維持する。
- 記録者: 同時実行中の別個体が同じ爆弾を捕らえられる。吸収試験を専用バッチへ分け、除去・回復・ブラックホール未発生の3条件は維持する。

両ローダーの実クライアントでGUI20画面の完了とPNG内の在庫表示を検査済み。公開成果物の昇格処理も、不足したテスト結果・内容が異なるJAR・不足したGUI画像を拒否することを確認した。

## 追加の再検証と配布方針

- 両ローダーの実クライアントで、斬撃・追従・帰還・画面外での帰還と実績ツリー・攻略本の撮影が完了した（Forge: combatFrames=62、NeoForge: combatFrames=34、両方 recall=true / recallCulling=true）。
- 採掘の独立再現12回で1回、納品2個の後に自然生成の砂利が落下して空気の判定を失敗させた。製品側は2個とも採掘していた。採掘列の上へ屋根を置き、回復量・時間・納品数は変更しない。
- 試作機の高速射撃試験では、無重力の標的が被弾後に吹き飛んで試験領域から出る影響を除くため、当該標的だけノックバック耐性を最大にする。突進後の光線が実際にダメージを与える条件は維持する。
- 旧保存の力場試験は構造物の外側にもプレイヤーを配置するため、外側24ブロックもチャンク準備・片付けの対象に含める。
- GUI試験のアンドロイドが消えたため、任意の地形をコピーした世界でも撮影室を空にし、天井を設け、開発専用の展示個体を無敵にする。通常のゲーム内個体は変更しない。
- **配布用JARはCurseForge限定。GitHub ReleasesにはJARを添付せず、変更履歴とCurseForgeへのリンクを掲載する。** Actionsの検証成果物は、検証済みの同一JARをCFへ送る工程で使用する。二重アップロードを防ぐため、アセットなしのドラフトでタグを予約し、CFへの送信成功後に説明文を公開する。
