# 0.9.0 / Minecraft 1.20.1 移植と検証

移植元: レビュー済みの`v0.9.0`。移植先: `1.20.1`のForge 47.4.26 / NeoForge 47.1.106、Java 17。

## 対応

- 0.8.1と0.9.0の公開された改善・修正を共有ソースへ取り込み。
- バックパック3段階、作業在庫と預かり箱、充電・止まった理由、許可証の判定、注文・預け入れ・検索の改善を維持。
- NBTの保存とクライアント同期、属性ID、機能の取得、描画、GameTestのAPIを1.20.1へ適合。
- Forge / NeoForgeで既存のMekanism化学4系統の連携を維持。
- 全251レシピを1.20.1形式へ正規化し、移植元の材料・数量・時間・電力・技術段階との一致をハッシュで検査。
- 5言語の説明と生成物を更新。既存のスロット番号・NBTの品物を保つ方針で実装。

先行検証で、テスト構造を床の配置前に記録する必要と、モックのゲームモード差を修正。あふれ検証が隣の構造の落下物まで数えないよう、検出範囲を自分の構造内へ限定し、独立したバッチで検査する。納品数と落下ゼロの判定は維持。収穫の畑は周囲の歩行面と同じ高さに置き、照明更新を待ってから植える。採掘のあふれ検査も同じ構造内に限定。戦闘タイミングの試験室は、自然地形の落下物や水が射線へ入り込まないよう外周と天井を閉じる。

Forgeの実クライアント検査で、設定保存後の非同期キャッシュ更新と一覧検索が競合するクラッシュを検出。読み取った設定が一時的に空なら既定値を使い、1回の並べ替えでは同じ値を使うよう修正。GUI検査でも設定キャッシュの並行更新を再現する。さらに旧ローダーのファイル監視をクライアントスレッドへ渡し、保存とTOML再読込が同じ表を同時に変更しないよう直列化。ローダーが自動保存するため明示的な二重保存を削除。検査では実際の再読込イベントのスレッドと保存後の設定値も確認する。また、複合モデルと視点別モデルのローダー名を1.20.1の`forge:`へ変換し、ソースと配布JARの検査へ追加。

## 検証構成

各ローダーで一般260件・自動化72件・リアクター21件・試作10件・進行13件・研究所15件、合計391件のGameTest。追加で各ローダーに実Mekanism連携2件。

GUIは各ローダーで実クライアント22画面・在庫欄105点を検証する。検索・並べ替え・新規注文・JEI双方向同期、ハンドブックの参照先とサイズ変更を操作する。

静的検査は翻訳、モデル、実績73件、支援者名簿、レシピ一致、Java 17の配布JARと1.20.1のリソース形式。公開時も全テスト群の正確な件数・同一ソース・同一JAR内容・GUI完了を照合する。

結果はPRの最新CIチェックを参照。全ティアの長時間通しプレイ、すべての他mod構成、実ユーザーワールド全種類の移行は未網羅。

## 公開

PRは`1.20.1`宛て。両ローダーの全チェック成功後にマージし、検証済みツリーのF/N別タグから同じCI成果物をCurseForgeへBetaとして送信する。GitHub ReleasesにはJARを添付しない。
